## 11. 死代码与分层体检（V3.0.0 起，每次大版本过一遍）

四条脚本化检查（**已入库在 `scripts/audit/`**，路径无关，换机器不用改），都能**跑出一份清单**，不靠眼睛看：

```bash
# ① 未引用的源文件 / 死导出 / 未使用依赖 / TODO / console / 临时文件
#    （输出为空即干净；「导出但只在本文件内用」属于风格问题，不是死代码）
node scripts/audit/dead-code.cjs && node scripts/audit/dead-exports.cjs

# ② 架构纪律：谁在直连底层（views/stores 直连 storage/sync/localStorage 应为空）
#    另含：定时器与事件监听是否成对清理 / JSON.parse 是否包 try / v-for 是否都有 key
node scripts/audit/layering-and-hygiene.cjs

# ③ 运行时：逐路由控制台报错 + 未捕获异常 + 404 + 可访问性抽查
#    （无头 Chrome + CDP，起服务与浏览器的写法见下方「附」）
node scripts/audit/runtime-check.cjs
```

**判定标准**：① 无死码（**有决策记录保留**的除外，且必须在文档里写明理由）；
② 页面层越层引用为零；③ 运行时零报错、可访问性抽查三项全零。

- [ ] 没有「导出后无人引用」的**函数 / 常量**（类型导出不在此列）
- [ ] `views/` 里没有 `@/services/*`、`@/sync/autoSync` 的直接 import
- [ ] 没有随旧 UI 移除后残留的令牌 / 别名（V3.0 清掉了 `--app-*` 与底部导航两项）
- [ ] 没有被下线功能的孤儿资源（图标 / 图片）——PWA 预缓存列表与实际文件一致

**退路**：

- **余额与流水加起来对不上** → 先分别看「流水列表里每一行的金额之和」与「余额卡」：
  两者**必然相等**（余额就是当场算出来的，没有第二份）。真对不上，先怀疑自己看的是
  不同范围（流水列表跟着「本月 / 本学期」切换，余额不跟），以及是否有批次行被折叠没看到。
- **批次金额 ≠ 已交人数 × 每人金额** → 两种可能：① 名单里有**重复记录**（同一学生两条，
  按学生 id 去重后只算一人，这是**对的**）；② 名单里有**已退档学生**（他们的勾仍然算钱，
  这是**故意的**）。都不是缺陷。
- **Excel 里金额列不能求和** → 立刻查 `buildFundFlowSheet` 是否把金额写成了字符串
  （本次刻意写数字，`fundExportXlsx.test.ts` 有断言守着）；能求和但**合计不等于余额**，
  则是口径问题——去核「导出恒为全部口径」那条钉子（页面里出现 `rangeTotals` 就会红）。
- **导出的文件里少了缴费名单** → 先确认**有没有批次**：没有批次时 PDF 只有一页、
  Excel 只有一张表，**这是设计**，不是漏了。
- **备份里没有班费** → 查 `src/utils/backup.ts` 的 `BACKUP_MODULES` 里那三行是否还在。
  漏登记的表现是「这个模块不参与备份」，**界面上看不出来**。
- **老师说「钱数不对」且说不清哪里不对** → 让他先看**流水列表**（一笔一笔都在），
  再看**批次的已交人数**。本模块没有「看不见的调整项」：余额只由流水决定，
  批次只由勾选决定，两者都不存在被悄悄改写的中间值。
