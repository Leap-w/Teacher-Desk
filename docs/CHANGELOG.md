## v0.13.0 —— Phase 9A：本机存储层抽象 + 同设备跨标签页同步（2026-09-11，commit `feat: phase-9a cross-tab sync and storage layer`）

**同一台设备上开两个入口（两个标签页，或标签页 + 已安装的 PWA 窗口）不再各改各的**：一边改了，另一边立刻跟上，不会出现「后写的把先写的整份覆盖掉」。这一步是后端接入的**地基**，**不需要任何云账号**——云端的部分（换设备同步）仍是下一步。

### 新增

- **同设备跨标签页同步**：同一个浏览器里开着两个入口时，一边改了学生 / 座位 / 课表 / 请假 / 值日 / 周末返家 / 待办，另一边**不需要刷新**就会跟上。覆盖面是**八个可写模块的全部**。
- **导入备份 / 清空数据后，其它入口自动整页刷新**：这两种操作是「整份换数据」（键可能新增也可能消失），另一边会在你操作完的那一刻重新加载，不会停在旧数据上。

### 变化

- **全应用读写本机数据收成一处**（`src/services/storage.ts`）：此前八个 store 各写一份「读 → 判断 → 写 → 失败告警」，备份模块自带一份端口实现、工具箱页面又照抄一份——同一个动作有三处实现，改一处要记得改十处。现在是**一个出口、一份实现**，写盘**幂等**（内容没变就不写）——这正是两个入口不会互相触发、无限来回的根据。
- **冲突口径（需求方 2026-09-11 拍板）：最后写入胜出**。整份数据写一个键，没有字段级合并；同设备下这是够用的（改哪一页都是自己改的）。
- 版本号 `0.12.0` → `0.13.0`（`package.json` + `appConfig.version`）。

### 边界（重要，别误会）

- **只覆盖同一台设备**。换设备、换浏览器**都不同步**；**iPhone / iPad 上的 Safari 与「添加到主屏幕」的 PWA 是相互隔离的存储分区**，前端读不到同一份数据——**那里前端做什么都无效，只有接后端才能统一**（Phase 9B）。
- 其它入口导入备份 / 清空数据后，本页会**直接重新加载，不弹确认也不提示**：那一页上正在填的表单会被刷新掉。这是有意选的——那两种操作本来就是「整个应用的数据都换了」，再问一句只会让两页短暂地显示不同的数据；表单内容是即时提交的，没有真正的未保存数据。

### 验证

- 四项验证全通过（prettier --check / vue-tsc --noEmit / eslint / build）；**111** 个源文件 / **19,505** 行；PWA **51** 个 precache 条目 / **1407.22 KiB**（**条目数不变、体积 −0.25 KiB**——没有新路由，而八处重复的读写代码收成一处，抵掉了新增的两个文件）。
- **跨标签页自检 79 项全过**（本项目新造的工具箱）：把「一个标签页」的模块用 esbuild **打包三份**，同一个进程里就有三套互相独立的 Vue / Pinia / store / sync 实例，共享一个内存 localStorage 桩（**逐键统计写入次数**）与**真实的 `BroadcastChannel`**，另在总线上挂第三个观察者数消息条数——测的是「两个入口真的互相跟上吗 / 会不会乒乓」这类**行为**，不是「函数被调用了」。断言覆盖：读写语义与幂等、A 改 → B 跟上、**静置后不许再有消息**、反向 B 改 → A 跟上、八个键各自「第 1 轮最多补写一次」+「第 2、3 轮完全静止」、远端脏数据被规范化收拾、整批重载广播。

### 交付前独立审查修复

- **旧课表迁移里「删旧键失败」不再兜底（本轮引入的回归）**：迁移成功后要删掉 Phase 4 的旧键，我为「有条目被丢弃时不删」加了分支却顺手去掉了删除自身的异常兜底——存储拒绝删除时，教师看到的是**空课表**，而新键里明明躺着一份完整的课表，之后随便改一门课还会把这份课表整份覆盖掉。现在删除单独兜一层：删不掉就留着旧键、下次启动再迁一次，不影响本次结果。
- **同步路径与加载路径给出一致的结果（姓名快照）**：首屏加载会刷新请假 / 周末记录里的姓名快照，而同步路径少了这一步——别人改了学生姓名后，本页会把**旧姓名**吃进内存，而列表里显示的正是这份快照。现在两条路径共用同一份归一化。
- **同步时读到坏数据不再用空列表覆盖**：某个键的内容损坏（写到一半 / 被外部工具改了）时，原先会把内存里的好数据清空、还顺手把空列表写回磁盘**冲掉原文**。现在读不动就**跳过本次更新**，盘上原文保留——与既有的「宁可不认，不可丢」口径一致。
- 另修：三处 JSDoc 堆叠（`loadXxx` 的说明压在了 `reviveXxx` 头上，注释与函数对不上号）；收到**没人订阅的键**时告警（键名写错的话数据永远不同步、界面上却看不出异常）。

## v0.12.0 —— Phase 8：首页仪表盘整合收尾（2026-09-11，commit `feat: phase-8 dashboard class overview`）

工作台补上**最后一张真卡片**：班级概况——三行回答「这个班现在什么情况」，首页自此没有占位。同一阶段统一了周末的人数口径，修掉一处「两张卡片加起来超过班级人数」的隐患。

### 新增

- **工作台「班级概况」卡片**：三行 **在读人数 / 今日值日 / 本周末留校**，**点哪一行就进哪个模块**（学生档案 / 值日管理 / 周末管理）。人数那行会说明「另有 N 位已退档，不计入」（还没有档案时提示去添加）；值日那行给出组名与「接下来：明天由「第 1 组」值日」，今天不值日或还没设起点时说明原因；留校那行同时给出「返家 N 人」。**「出勤」按需求方 2026-09-11 拍板本阶段不做**（依赖仍在未排期的考勤记录）——卡片只有三行，**不留占位、不假装有数据**。
- **首页占位卡片归零**：`DashboardCard` 类型与首页的占位卡渲染、空态组件、手写 chip 样式一并删除。首页现在是**八张真卡片**（占位**页**此前已在 Phase 6 归零）。

### 变化

- **周末人数的口径统一为「只算在读学生」**（本次最要紧的一条）：所有人数——本周末返家、切换条上每期的人数、本月人次、留校——**只数在档案里的学生**；已退档学生的历史记录**仍列在周末页名单里并标注「已不在档案」，只是不计入任何数**。此前这条口径只在周末页里落实，工作台卡片与切换条仍按记录条数算，于是可能出现「在读 5 人 / 留校 4 人」与「本周末返家 2 人」加起来超过班级人数的画面。现在**在读 N 人 = 留校 S 人 + 返家 R 人**在班级概况卡片、周末返家卡片与周末页里处处成立；周末返家卡片也会多一行「另有 N 条已不在档案的登记，不计入」。
- **值日「今天值不值日」的判定与「下一次是谁」的文案改为两张卡片共用一处**：此前今日值日卡片与班级概况卡片各写一套判断顺序，**「有值日组但还没设轮换起点、且今天正好是周末」**这一种情况下，上方横条说「还没设置轮换起点」、页脚却说「值日组与轮换设置都在值日管理页」——现在统一提示「还没设置轮换起点」。
- 版本号 `0.11.0` → `0.12.0`（`package.json` + `appConfig.version`）。

### 验证

- 四项验证全通过（prettier --check / vue-tsc --noEmit / eslint / build）；**109** 个源文件 / **19,217** 行；PWA **51** 个 precache 条目 / **1407.47 KiB**（**条目数不变**、体积 +4.13 KiB——本阶段没有新路由，只是首页组件与 store 换了几处代码）。
- 数据层自检 **38 项** + SSR 渲染验证 **23 项**（含跨卡片一致性：在读 = 留校 + 返家、卡片徽标与姓名标签个数对得上、退档学生不出现在标签里、值日那行与今日值日卡片说的是同一个组），并做了**变异验证**（去掉在读过滤 / 打乱判定阶梯 / 交换首页属性，分别报 4+7 / 3+1 / 3 项失败——断言不是空的）——**全过**。

- 另记录两条**既有边界**（非本阶段引入，本阶段不修并写明理由）：轮换起点设在未来时两张卡片仍报「今天值日 = 某个组」（要连值日页一起改，留待值日增强成套处理）；今日值日卡片页脚「共 N 人」把已退档组员算在内（值日口径留待下次统一）。

## v0.11.0 —— Phase 7B：周末管理（2026-09-11，commit `feat: phase-7b weekend management`）

回答班主任每周五都要问的一句话：**这个周末谁不在学校**。工作日里学生回家住不住校，学校要的是「谁返家」这一件事的准确名单，所以这一期只做名单：**登记返家 = 一次点选若干学生**，留校不落库、由名单反推。周末管理因此不是请假的复制品——**不设审批、不记时长、不记离校 / 返校时间**（2026-09-11 需求方拍板，逐条见开发手册 §9.17）。

> 编号：Phase 7 分两步走（2026-09-10 拍板）。**7A** 先把「日期 + 上午 / 下午」形状的公共流程骨架从请假模块抽出（`refactor: phase-7a shared register skeleton`，纯重构，**不单独打 tag**，见 §9.16）；**7B** 用骨架实现周末管理并交付本 tag。因 7B 实际只需要「是否返家」一个事实，7A 抽出的登记弹窗 / 状态行在本阶段**没有消费方**（§9.17 已记，不假装在用）。

### 新增

- **周末管理页 `/weekend`**（一级导航新增「周末管理」，工作台卡片直达）：顶部是**周末切换条**——列出「已有记录的周末 ∪ 本周末 ∪ 下周末」，按时间倒序，每期带返家人数；分节头给出**返家 N 人 · 留校 M 人**；下面是这一期的返家名单（序号 + 姓名快照 + 删除按钮，删除走二次确认弹窗）。留校人数**按在读人数派生**（在读 − 该期名单里仍在读的人），不落库——「没登记的学生即视为留校」写在空态文案里，教师一眼知道不登记不会漏掉谁。
- **登记返家抽屉**：填日期（**填周六或周日均可，按该周周六登记**；填到周一~周五会当场报错，不猜是不是「下个周末」）+ 勾选学生（仅列在读学生，搜索姓名 / 学号；**这一期已经登记过的人自动置灰并标注「已登记」**，避免同一人在两个入口重复登记）。一次登记若干人，写入后停留在刚登记的那一期——教师的下一步就是核对名单。学生**只增不删**式写入：撤销某条登记由名单上的删除按钮负责，不会被覆盖式写入抹掉「学生已被删除、表单里再也选不到」的历史记录。
- **工作台「周末返家」卡片**：本周末返家 N 人 + 姓名标签（**最多 8 个**，其余折成「还有 N 人」）+ 本月累计 N 人次，点进 `/weekend`；本周末无人返家时给空态与「登记返家」按钮。
- **数据层**：`teacherdesk:weekendReturns`（第八个可写 store）+ `utils/weekend.ts` 纯函数 + `types/weekend.ts`。周末键**统一用该周周六的日期键**（周日归到前一天），不引入 ISO 周号——跨年、第一周从哪天算起这类分歧只会制造对不上的表格。
- **数据管理第八块「周末返家」**：进入概览 / 导出备份 / 合并导入 / 清空示例数据（示例记录以 `weekend-` 前缀识别）。
- **示例数据 5 条**（本周末 3 人 + 上周末 2 人），且**仅在示例学生都还在读时**才写——`teacherdesk:weekendReturns` 是新键，从 v0.10.1 升级上来的教师第一次打开也满足「首次启动」，无条件播种会让别人家的学生凭空出现在你的名单里。「还在读」是判据的关键一半：退档的学生仍留在档案数组里，只看 id 在不在会把「已把示例学生全部退档」的教师误判成「档案还是示例数据」（见下方审查修复）。

### 变化

- 版本号 `0.10.1` → `0.11.0`（`package.json` + `appConfig.version`）；PWA manifest 描述补上「周末管理」。
- `services/index.ts` 与工具箱的模块计数改为八个；`stores/app.ts` 的过时注释（「模拟同步，Phase 7 替换为真实 API 调用」——后端其实是 Phase 9）改正。

### 交付前独立审查修复（12 项，含 3 项真缺陷）

- **【跨模块】播种守卫把已退档的示例学生当成「档案里还有」**（`stores/weekend.ts` / `stores/leave.ts` / `stores/duty.ts` 三处同一口径）：判断「学生档案还是不是示例数据」时只查了 id 在不在数组里，**但软删除的学生仍留在数组里**——于是「把示例学生全部退档」的教师被判成「档案仍是示例数据」，被凭空播种 5 条已退档学生的返家记录（请假 3 条、值日同）。三个 store 一律改为「示例学生**都还在读**」（`!deletedAt`）才播种。
- **「返家 + 留校」会超过班级人数**：名单里留着已退档学生的历史记录，原实现拿记录条数当返家数。改为只统计**仍在读**的人，并补注「另有 N 条已不在档案的返家记录，仍列在下方」——**历史照样列出来，只是不计入这两个数**。
- **撤掉某一期最后一条记录后，页面停在切换条里不存在的期次**（死界面）：`weekendKeys` 只列「有记录的周末 ∪ 本周 / 下周」，该期撤空后就从切换条消失了，于是没有高亮、也切不回去。改为撤销后若当前期次已不在切换条，回落本周末。
- **登记抽屉固定回落到本周末**：登记成功后页面会跳到刚登记的那一期，教师再点「登记返家」时抽屉默认日期与眼前的名单不是同一期。改为跟着当前选中的期次走。
- **工作台底部写死三列**：7B 之后这一行有 4 张卡，第 4 张会独自折到第二行、右侧空出三分之二。改为自适应列宽（桌面 4 列、窄屏回落 3 列）。
- **返家姓名标签拿姓名快照当 `v-for` 的 key**：快照是「姓名（学号后四位）」，同名且学号后四位相同会撞 key。改为以记录 `id` 为 key。
- 其余：姓名快照维护抽成 `utils/student.ts` 的 `refreshStudentNames`（7B 原先从请假 store 逐字复制了第二份，违反手册 §11.1）、七处「注释比实现乐观」、`0 条` toast 说出假原因、留校公式注释与页面实现不一致、工作台卡片空态文案与徽标自相矛盾、手册 §9.17 自身的悬空引用。

- **【中】导入是不可逆覆盖，却没有「先导出」的提示**：与「清空全部数据」口径对齐——弹窗写明「被覆盖的版本无法找回」，并提供「先导出当前备份」按钮（不关闭弹窗即可导出）。

- **【低】**：「没有可合并的记录」时确认按钮仍可点 → 一并禁用；清空全部数据的成功提示「N 个数据块」与实际列表对不上 → 去掉数字、列表过滤 0 条并标出「读取异常」块；导出失败无任何提示 → 补 toast；错误文案里的开发者词汇（「顶层」「列表」「缺少 id」）改为教师能看懂的说法；`teacherdesk:notice` 未走 `storageKeyPrefix`（补齐）；面向教师的页面上出现仓库路径（移除）；合并表补 `scope="col"`；隐藏的文件选择框补 `aria-hidden`；表格间距改取 token。
