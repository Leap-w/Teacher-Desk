## v1.1.1 —— 学生档案升级：Phase 5A + Phase 5B（2026-09-12）

> **一版只动学生档案，分两步走、同打一个 tag**（`v1.1.1` 先指向 5A，5B 交付后**移到 5B 提交**）：**Phase 5A** 解决「怎么把 63 个人弄进系统」，**Phase 5B** 把它做成「好用」。**不新增模块 / 路由 / 一级导航**，**不碰座位图 / 请假 / 值日 / 周末 / 课表 / Widget / 同步逻辑**。
>
> - **Phase 5A**：① **Excel 批量导入**（本阶段主体）；② **宿舍改固定 8 间**；③ **`seatNumber` 撤出界面**；④ **卡片顺序与内容调整**；⑤ 班委可自定义、学号改选填。详细设计与取舍见开发手册 **§9.24**。
> - **Phase 5B**：⑥ **检索增强**（搜索补上班委）；⑦ **固定三种排序**（默认 / 首字母 / 随机）；⑧ **批量编辑**（宿舍 / 班委 / 标签）；⑨ **卡片视觉细节**；⑩ **搜索状态刷新后恢复**。详细设计与取舍见开发手册 **§9.25**。
>
> **Phase 5B 明确不做**：**学生头像**（需求方 2026-09-12 明确「不再做学生头像了」，`StudentAvatar.vue` 一行未动）、**批量删除**、云端头像存储、自动排座新策略、卡片组件结构重构、任何颜色体系改动。

### 新增

- **Excel 批量导入**。入口在学生档案页工具栏「批量导入」与空态按钮；弹窗内选 `.xlsx` / `.xls`（≤ 5 MB）→ 预览 → 确认导入。预览给**五格统计（总行数 / 可导入 / 被拦下 / 其中新增 / 其中更新）+ 提示组 + 逐行表格**（行号 · 姓名 · 性别 · 学号 · 宿舍 · 班委 · 标签 · 状态），被拦行整行标红并给出原因；**关闭弹窗不写入任何数据**。
- **`src/services/studentImport.ts`**：切成两层——`readSheetRows`（唯一碰 xlsx 与字节的一层，**动态 `import('xlsx')`**）与 `parseStudentRows` / `planStudentImport`（**纯函数**，分流规则、异常判定、字段覆盖口径与统计全在这里）。**规则放纯函数层，是为了能在 node 环境的常驻测试里直接被喂数组跑**——本仓库不装 jsdom，规则若写进读文件那一层就只能开浏览器点着试。
- **`studentStore.applyStudentImport(plan)`**：整批**一次性替换学生数组** = **一次写盘 + 一次广播**（逐行调 `addStudent` 会写 N 次盘、广播 N 次）。有测试断言写盘次数为 1。
- **宿舍固定清单（新的唯一事实源）**：`DORMITORIES`（女生2栋113–116 / 男生1栋209–212）、`ALL_DORMITORIES`、`dormitoryOptions(gender)`、`isValidDormitory(value, gender?)`——表单、导入校验、迁移收敛三处共用。
- **班委「＋ 自定义」**：预设职务之外可录入任意职务。哨兵值绝不写入模型；既有自定义职务打开表单时**回填成「＋ 自定义 + 输入框」**，否则原生 `<select>` 找不到匹配项会显示成「无」，一保存就把职务抹掉。
- **标签自动换行**与**班委徽章（松石青 primary）vs 标签徽章（中性灰）**的视觉区分——前者已有的 `flex-wrap` 无需改动，后者本就有，本版只调整了卡片上的块顺序。

### 变化

- **宿舍从自由文本改为固定 8 间的下拉**：改性别后若已选房间不属于新性别则**立刻清空**（原生 `<select>` 会显示空白但提交时旧值仍在 form 里，等于把女生悄悄存进男生楼）。导入时宿舍不在清单内**只提示不拦**：学生本身有效，不该为了一间写错的宿舍丢掉整条档案。
- **`seatNumber` 从界面撤下**（表单 / 卡片 / 详情都不再显示、不再编辑），**模型字段保留**——「＋ 新建方案」与自动排座播种仍按它自动就座。表单提交 payload **刻意不带这个键**：`updateStudent` 是浅合并，不传即保留原值。**座位图零影响**：面向用户的「N 号」始终来自座位图的行列几何位置，`seatAccentOf` 也不读 `seatNumber`。`formatSeatLabel()` 已删除。
- **学生卡片**：块顺序改为 **① 班委 → ② 标签 → ③ 宿舍 → ④ 联系电话**，四块无内容不占位；**不再显示返家信息**（删返家范围徽章）；学号为空显示占位「—」。
- **学号改选填**：允许为空且**空值之间不查重**（拿空串互相判重，第二个「还没填学号」的学生就存不进去了）。
- **展示名分两个口径**：**档案模块**走 `formatStudentShortName()`（`姓名（学号后四位）`，不含座位号）；**座位图 / 请假**仍走 `formatStudentDisplayName()`（含「N 号」）——**一字未动**。理由：座位号已从档案界面撤下，档案里再显示「1 号」就是个教师改不了也无处可查的数字；而座位图上那个号描述的是眼前的格子。两者是同一套消歧规则，**没有新写第三个格式化函数**。
- **示例数据**（`services/mock.ts`）：6 名种子学生的宿舍改为清单内的值。**必须改**——首次播种直接 `return seed`、不过 `normalizeStudent`，种子值不在白名单内会导致「第一次打开显示旧值、第二次打开被清空」的肉眼可见闪变。
- **依赖新增 `xlsx@0.18.5`**（npm 上该包的最后一版，`^0.18.5` 不会漂移）。**`npm audit` 报 2 条 high**（CVE-2023-30533 原型污染 / CVE-2024-22363 ReDoS），**均需解析恶意构造的文件才触发**，而输入是教师自己的班级名单——**记录在案，未修，也不跑 `npm audit fix --force`**（那会把包换成另一个实现）。
- **版号 `1.1.1`**：`package.json`、`package-lock.json`（顶层与 `packages[""]` 两处）、`src/config/index.ts` 的 `appConfig.version`。**macOS 侧 `MARKETING_VERSION` 保持 `1.0.0` 不动**——本版是纯 Web 改动，`macos/` 一个字节没碰。

### 数据迁移（**升级前先在「工具箱 → 备份」导出一次 JSON**）

- **宿舍白名单收敛**：`normalizeStudent()` 里，`dormitory` 有值且不属于 8 个合法房间之一 → **置空**（性别可识别时按该性别的房间校验）。触发点仍是这一个函数，它同时服务**首屏加载 / 跨标签页同步 / 云端同步**三条路径，所以三条自动一致。
- **为什么是白名单收敛而不是「一次性清空 + 迁移标记」**：两者对现存数据的实际结果完全一样（现存值全是「3 号楼 412」这类自由文本，一个都不在白名单里），但白名单收敛是**幂等**的——一次性标记只在升级那一刻生效，之后从备份恢复或从云端拉回旧快照，旧值会重新冒出来且**永不再清**。已用常驻测试锁住幂等性。
- **⚠️ 后果一：所有现存宿舍值会消失**，包括教师自己录入的与示例数据里的。
- **⚠️ 后果二：写盘文本变化 → 首次同步保护降级**。`writeSeedJSON` 的播种基线按原始文本比对，收敛后文本不再匹配，新设备首次同步会把这批学生当成「教师自己的数据」，于是**弹出合并询问**而不是静默采纳云端——**表现为多一次确认弹窗，不会丢数据**。
- **⚠️ 后果三**：座位快捷卡（`SeatQuickCard.vue`）上的宿舍在迁移后会显示「—」，直到重新编辑——该文件本版未动（不在范围内）。
- **导入进来的学生没有「所属地区 / 县区」**（Excel 里没有这两列）；**返家范围是可选列**，认正式文案与「市区 / 其他县 / 市外 / 区外 / 外地」等短写，预览会统计「N 行缺返家范围」。

### 导入口径（拍过板，改之前先看）

- **列按名字认，不按位置**（表头里的「（必填）」这类后缀会被剥掉）；**缺「姓名」或「性别」列 → 整体报错**，不进预览。
- **按学号追加合并**：命中库内**未软删**学生 → 更新，否则新增。**绝不按姓名合并**（会把两个「旦增卓玛」合成一个人，且丢掉的档案不可恢复）。
- **更新只覆盖这一行确实填了的字段**，空单元格 = 「本次没填」而不是「清空」——那些格子在 Excel 里本来就是空的，教师看不出发生了什么。代价：**导入无法清空字段**，要清得手工编辑。
- **拦的只有两条**（+ 性别无法识别）：空姓名、**表内**学号重复（只留第一行并指出「与第 N 行重复」）；其余（重名 / 宿舍不在清单内 / 缺返家范围 / 学号为空）**只提示不拦**。**被拦的行绝不进计划**——预览说「拦下 3 行」，落库就不能多出人来。
- **学号为空不参与匹配**：没有键可匹，每次导入都会新增一条，预览必须显式提示。
- **预览数字与落库计划同源**：合并计划是 **computed、依赖学生表**，不是「选完文件算一次」，避免「预览说新增 40、落库变成 41」。
- **`checkFileSignature` 挡在 xlsx 之前**：SheetJS 的 `read` **会自动嗅探 CSV**，纯文本喂进去它照样「成功」且按 latin1 解码（`姓名` 变 `å§å`）——教师把 CSV 改名成 `.xlsx` 后只会看到「没有找到「姓名」列」，而表头明明写着「姓名」，错在格式、提示却指向内容。故先按文件头判类型（`.xlsx` = ZIP `PK`，`.xls` = OLE2），两者都不是就明说「这不是 Excel 文件，请在 Excel 里另存为 .xlsx 再导入」。

### 构建产物

- **xlsx 没进首屏**：产出独立分块（429.19 kB / gzip 141.77 kB），**入口 chunk 体积与上一版完全相同**（917,700 字节 = 917.70 kB）；用 `SheetJS` / `sheet_to_json` / `aoa_to_sheet` 等特征串 grep 入口分块全部未命中。**白拿的好处**：xlsx 也被 Service Worker 预缓存（49 项 / 2616.75 KiB，上一版 48 项），**离线也能导入**。

### 验证

- **交付链五项全过**：`npx prettier --check .` / `npx vue-tsc --noEmit` / `npm run lint` / `npm run test` / `npm run build`。
- **常驻测试 81 → 115 项**（5 个文件）：新增 `studentImport.test.ts` **34 项**（表头识别 / 逐行校验 / 合并分流 / `readSheetRows` 读真造的 xlsx / 落库只写一次盘）；`revive.test.ts` 补 3 项（宿舍白名单收敛、**收敛幂等**、空学号不参与查重）。
- **手工端到端**：用真实管线造了一份覆盖全部异常类别的 7 行脏名单（空姓名 / 表内学号重复 / 宿舍非法 / 性别无法识别 / 重名 / 空学号 / 与库内学号重复），逐行状态与提示均正确（总 7 / 可导入 4 / 拦下 3）。

## v1.1.1 · Phase 5B —— 学生档案升级（收尾）：检索、排序、批量编辑与展示优化（2026-09-12）

> 与 Phase 5A **同版同 tag**（tag `v1.1.1` 已移至本提交）。**只动学生档案模块内部**（加一处服务层 + 三处纯函数层新文件），**不新增模块 / 路由 / 一级导航**。

### 新增

- **统一检索出口**。列表的数据管道 `students → filter → sort → render` 收敛成**一个 computed**（`visibleStudents`）。规则本身全在纯函数层 `src/utils/studentQuery.ts`（`queryStudents()` / `buildRandomRanks()`），store 的 `searchStudents()` 改为**委托**它——**过滤与排序从此只有一份实现**，且能脱离浏览器单测。
- **搜索增强**：haystack **补上 `cadreRole`**（在这之前搜「班长」是零结果，而班主任最常找的就是班长和学习委员）；范围＝姓名 / 学号 / **班委** / 宿舍 / 标签，trim + 不区分大小写；占位符改为 `搜索姓名、班委、宿舍或标签…`。
- **固定三种排序**（分段按钮，与既有性别筛选同款同行）：
  - **默认**：学号升序，**空学号一律排最后**（对 Phase 5A 副作用的正——空串与数字串比较会排到**最前**，那批「还没补学号」的学生曾顶在名单头部）；
  - **首字母**：按姓名全拼（`pinyin-pro@3.29.4`，`toneType: 'none'`），**同拼音保持原序**（比较相等返回 `0`，交给 `Array.prototype.sort` 的稳定性）；
  - **随机**：**每次点击重新洗牌**（含「已经是随机时再点一次」）、**当前会话保持结果**（切到座位图再切回来顺序不变）、**不写 localStorage**、**不修改 `students`**。
- **批量编辑**（入口：学生档案工具栏「批量管理」，页内模式切换）：多选 / 全选（＝**当前可见**）/ 取消全选；批量修改**宿舍**（复用固定 8 间）、**班委**（复用预设 + 自定义）、**标签**（添加 / 移除指定标签，自动去重）。**暂不支持批量删除。**
- **`src/utils/studentBatch.ts`**：`buildBatchPatch(student, changes)` 把「一个学生该被改成什么」算成补丁，纯函数、可单测。
- **`src/utils/studentViewPrefs.ts`** + 独立键 `teacherdesk:studentView`：**搜索词与排序方式刷新后恢复**。
- **`src/services/pinyinSort.ts`**：唯一碰 `pinyin-pro` 的一层，`loadPinyinKey()` 动态 `import()` + 模块级缓存 + 失败返回 `null`（由调用方 toast 提示并回落默认排序）。
- **`src/views/Students/components/StudentBatchEditModal.vue`**：批量修改弹窗。
- **依赖新增 `pinyin-pro@3.29.4`**（**动态 import**，见下「构建产物」）。

### 变化

- **列表页工具栏**「批量导入」+「＋ 新增学生」之外新增「批量管理」；批量模式下换成 `已选 N 人` · 全选 · 取消全选 · 批量修改（选中数为 0 时禁用）· 退出批量管理。
- **学生卡片加 `selectable` / `selected` 两个可选 prop**：批量模式下右上角出现原生 checkbox，**点卡片本身 = 勾选**（不弹详情，否则想勾一个人得先关掉弹窗才能继续选）。`StudentAvatar.vue` **一行未动**。
- **卡片视觉细节**（全部写在 `StudentCard.vue` 的 scoped CSS 里，**不动全站共用的 `AppCard` 本体**）：空字段规则**固化为「身份区（姓名 / 学号）用占位符『—』，补充区（班委 / 标签 / 宿舍 / 电话）整块隐藏」**；标签补 `overflow-wrap: anywhere`（`AppBadge` 自带 `nowrap`，长标签原先会**溢出卡片边界**而不是换行）；间距统一到 `--space-3` 并**删掉 `.badges + .line` 相邻兄弟选择器**（它只在宿舍非空时成立，宿舍空而电话有时会少一档间距）；`:active` 补轻微下沉、`:focus-visible` 用现成但闲置的 `--ring-focus`。**只引用 `theme.css` 的变量，不新增任何色值，颜色体系一字未改。**
- **事实源上移**：`CADRE_OPTIONS` / `PRESET_CADRES` / `CADRE_CUSTOM` 从 `StudentFormModal.vue` 移到 `src/utils/student.ts`（批量弹窗要用同一份），表单改为 import，**行为不变**。
- **`studentStore.applyStudentBatch(ids, changes)`**：批量修改落库，整批**一次性替换学生数组** = **一次写盘 + 一次广播**；**一个人都没变时不赋值**（不写盘、不广播）。组件层**绝不循环调 `updateStudent()`**。
- **`searchStudents()` 的选项**扩为 `keyword / gender / cadreOnly / sort / pinyinKey / randomRanks`（全部可选，签名**向后兼容**）。

### 口径（拍过板，改之前先看）

- **「不修改」与「清空」严格分开**：弹窗用哨兵值 `__unchanged__` / `__clear__` / `__custom__` 表达「这次怎么处置这个字段」，**哨兵值绝不写进模型**。拿空串表示「不修改」的话，教师就永远批量清不掉一个字段。宿舍「未分配（清空）」与班委「清空班委」两项都给。
- **`buildBatchPatch` 三种返回值刻意分开**：`null` = **不适用**（目前只有「所选宿舍与该生性别不符」）→ 计入 `skipped`；`{}` = 适用但**改完与现状完全一样**（如标签本来就已存在）→ **不计入任何计数**；非空对象 = 真的变了。**「没变化」若算进 `skipped`，教师会看到一句莫名其妙的「跳过 63 人」。**
- **性别不符不「尽力而为」地写进去**：`normalizeStudent` 的宿舍白名单收敛会在下次加载时清掉错性别的房间——**写进去也是一个会自己消失的值**，教师却会先看到它生效了一瞬间。
- **宿舍下拉列出全部 8 间，不按性别收窄**：一次选中的学生可能男女都有，选项取决于谁被选中会让人猜不透；匹配交给落库前的校验去挡，挡不住的跳过并报数。
- **随机排序用「洗牌后的位置」而不是随机数**：随机数会撞值，撞值就得再定一条并列规则；洗牌后的位置天然是无并列的全序。**没被洗进权重表的学生**（洗牌之后才新增的）排到最后，而不是插到最前。
- **「当前会话保持结果」的实现方式**：`index.vue` 的**普通 `<script>` 块（模块作用域）**里放 `sessionSort` / `sessionRandomRanks`——放组件里会在路由离开时随组件丢掉，放 localStorage 又违反「随机不落盘」。**刷新页面 = 新会话，重新洗牌。**
- **排序控件是分段按钮而不是下拉**：浏览器对下拉里「选中已选中项」**不派发 `change` 事件**，「每次点击重新随机」用下拉做不到。
- **拼音词典未就绪时排序退化为默认序**（不是「点一下没反应」）；**加载失败时回落默认排序并 toast 明说**。

### 变化

- **首次同步收紧（本阶段唯一涉及用户行为的调整）**：此前（9B）首次同步**以云端为准**——本机已有教师录入的数据时，那份数据会被云端那份静默覆盖。现在分两种处境：**情况 1** 本机没有真实业务数据（键不存在 / 空列表 / 仍是播种原文）→ 照旧以云端为准（新设备装上就该看到已有数据）；**情况 2** 本机已有真实数据（学生档案 / 座位方案 / 课表 / 请假 / 值日 / 周末返家 / 待办）而云端也有 → **不静默覆盖**，报出待裁决的键，**本机与云端一字未动**，等教师在工具箱里选「保留本机并上传」或「保留云端并覆盖本机」。**不做复杂合并 UI、不做字段级合并、不做自动智能合并**——两条都是真数据时，同步没有资格替教师丢掉任何一份。首次同步**之后**同一项两边都改过，仍按 9B 拍板的**最后写入胜出**（那是明示规则，不是静默丢弃）。
- **「本机有没有真实数据」的判据是播种基线原文**，不是示例 id 前缀：id 前缀判的是「这条记录怎么来的」，原文判的是「教师动过没有」——首次同步要问的正是后者，因此教师改过任何一字就自动失配。
- **「清空全部数据」改名为「清空本机数据」**，并在已登录时明说「不会删除云端数据，下次同步时可能重新出现在本机；要连云端一起清，得去云开发控制台删除该集合里的文档」。**文案之外没有行为改动**——「要不要加『同时清空云端』」需求方 2026-09-12 拍板**不做**（这个工具是工作台，不是记录系统）。
- **冲突是界面上的一个状态，不是同步失败**：`cloudSyncState` 增 `conflicts`（与 `status` 正交：一个说「这一轮通不通」，一个说「有个问题只有教师能回答」）；工具箱出现冲突区块与确认弹窗，顶栏「同步」按钮遇到冲突提示一句并把人送到工具箱，`statusView` 首行显示「需要确认」。冲突列表**只活在内存**，刷新后由下一轮同步重新发现。

### 缺陷修复

- **「点登录没反应」**：用户名输入框写的是 `type="email"`，教师填自己建的用户名时**被浏览器自己的校验挡在提交之前**（提示「请输入邮箱」）——**请求根本没发出去**，云端不会有任何错误可查，界面上也没有任何东西可看。改 `type="text"` + `autocomplete="username"`。**这类缺陷自检抓不到**（它不在 `cloudSync.ts` 的纯逻辑里，而在 DOM 的原生校验上），是这次联调暴露出的盲区。

## v0.14.0 —— Phase 9B：腾讯云 CloudBase 云端同步（2026-09-11，commit `feat: phase-9b cloudbase sync`）

**同一个账号下，换设备 / 换浏览器现在看到的是同一份数据**：手机记的请假、电脑录的座位，各端会自动对齐。数据仍然**本地优先**——没网照常用，联网后自动补齐。Phase 9A 让**同一台设备**的两个入口互相跟上，这一步补上**跨设备**那一半（iPhone / iPad 上 Safari 与「添加到主屏幕」的 PWA 那两套彼此隔离的存储分区，也正是靠这一步统一的）。

### 新增

- **云端同步卡片**（工具箱页面，数据管理卡片下方）：邮箱 + 密码**登录 / 注册**，登录后立即对齐一次；卡片显示状态（已同步 / 正在同步 / 未登录 / 连不上云端 / 同步出错）与当前账号，另有**「立即同步」**与**「退出登录」**。出错时**原样显示云端返回的原因**——不编「某某错误码 = 某某中文」的对照表（那种表一旦猜错，教师会照着一条假指引去操作）。
- **自动同步的四个时刻**：应用启动、本页改动之后（合并连续编辑，1.5 秒后发一次）、重新联网、页面回到前台。教师不需要记着点同步。
- **离线优先**：改动先写在本机（**磁盘就是待发队列**），联网后一轮补齐；页面刷新、关掉重开都不丢待发内容。

### 变化

- **一个模块 = 云端一份文档，整份对齐**（不做字段级合并）：教师改哪一页都是他一个人改的，字段级合并换不来可见的好处，却会引入「两边各改了一半、合起来谁都没写过」这种查不出的状态。
- **冲突＝最后写入胜出**（沿用 Phase 9A 拍板口径）：两边都改过时后写的赢。**首次同步以云端为准**——新设备装上就该看到已有数据，而不是把它自己播种的示例数据推上去把真实数据盖掉；两边时刻相同时判云端赢。
- 版本号 `0.13.0` → `0.14.0`（`package.json` + `appConfig.version`）；工具箱那一页不再只是「备份与恢复」，同步入口与备份入口放在一起——它们是同一件事的两种形态：把数据放到别处留一份。

### 边界（重要，别误会）

- **首次使用要在 CloudBase 控制台做准备（应用自己办不到）**：① 为环境 `teacher-desk-d6gdsgqb8f9dc13d2` **开启邮箱登录方式**；② **建 `teacherdesk` 集合**；③ 权限选**「仅创建者可读写」**。⚠️ **不要用「匿名登录 + 所有人可读」**——一个账号里装的是全班学生的姓名 / 学号 / 家庭住址 / 请假与返家记录，放开读等于任何拿到环境 ID 的人都能整份拷走。
- **本地清空 ≠ 云端清空**：「清空全部数据」清的是**本机**（含同步记账），云端那份还在——重载后同步会把它取回来。**数据不会丢，但「清空」不会真的空**；要真清空得先退出登录，或在控制台删掉集合里的文档。要不要加一个「同时清空云端」的选项，**属业务决策，待需求方拍板**。
- **在一台设备上删掉整份数据的意图不会传到另一台**：云端「没有这个键」是合法状态（清空数据会移除键、应用重载会重新播种），因此**不把云端缺失当成删除指令**——否则云端一次误删会顺着所有设备把数据清干净。
- **两端的系统时钟之差会直接变成胜负偏差**（冲突比的是各自本机写下的时刻）。
- **首屏体积变大**：PWA 预缓存 **1407.22 → 2175.36 KiB（+768 KiB）**，全部来自 CloudBase SDK 静态进主包（入口 chunk 906.41 kB）。若日后在意，可改成「登录时才动态加载」。

### 缺陷修复

自检发现：

- **采纳云端数据之后会多推一轮**：各模块的归一化（如请假记录补姓名快照）是**异步**写完盘的，而「这份原文已与云端对齐」的记录抢在它之前做，于是下一轮把这次归一化当成了「本地又改了」再推一次——两台设备之间于是来回多推。改为**先让归一化落盘、再记录对齐**。
- **刚改完的设备会被另一台稍早的推送盖掉**（把「最后写入胜出」判反了）：冲突判定读的是**上一轮**留下的本地写盘时刻，比的就成了「上次对齐」而不是「这次写入」。改为判定前先从写盘记录里取当前时刻。

交付前独立审查（两个互不重叠的审查面并行跑，**各自独立撞到了同一批问题**）：

- **⚠️ 改动可能在重开应用后被云上旧版本整份盖回去（数据丢失级）**：冲突判定要拿「本地这份什么时候写的」和云端的时刻比大小，而这个时刻原先只活在内存里、且只由一条写盘路径登记。于是①**跨会话就整表丢失**——上个会话改完、那一轮同步又没跑完（断网、进程被杀），重开应用后判定退回**上一轮**的旧时刻，「最后写入胜出」被判反，教师刚改的数据被云端更早那份盖回去；②**工具箱的合并导入与两档清空**绕过那条路径直接写盘，同样判反。修法：把登记点**下移到存储端口**（任何路径写盘都自动登记），并把时刻表**落盘**（`teacherdesk:localWriteAt`，不进备份、不参与同步）。
- **弱网下单个键推失败，界面却报「已同步」**：循环里记下了失败，循环后却**无条件**把状态清成「空闲、无错误」。一轮里前七个键推成功、第八个超时，教师看到的是绿点与「已同步」，放心去换设备，而那个模块的改动还留在本机。改为**有失败就不报「已同步」、也不更新「上次同步」**。
- **采纳时没看本地到底写没写进去**：存储写失败（配额满 / 隐私模式）时盘上还是旧内容，却照记「已与云端对齐」——下一轮会把旧内容当成本地改动推上去，把云端那份盖掉，而它从未真正被取下来过。改为**把盘上内容读回来比对**，不一致就不算采纳。
- **断网时界面说「未登录」**：把「查不出登录状态」折成了「没登录」，于是离线启动的教师看到登录表单，以为掉登录了、在没信号的地方反复输密码。改为**只在确实没登录时才算未登录**，查不出来时按联网状态显示「连不上云端，暂时无法确认登录状态」，并且**不摆登录表单**。
- **同步进行中再点「立即同步」会报假的失败**：第二次点击立刻返回、读到的是中途状态，于是走「不是空闲就是失败」那条分支，弹出「同步没成：原因未知」。触发极常见（改动后 1.5 秒内、启动首轮、回到前台都在同步中）。改为**等这一轮跑完再返回**、同步中禁用按钮、登录失效时单独报「登录状态已失效」。
- **退出登录没清同步记账**：记账记的是「本机这份原文已与云端对齐」，那是**账号级**的事实。不清掉的话，下一个在这台设备上登录的账号会沿用上一个账号的对齐状态——本机数据被当成「早就对齐过、没改过」而既不下发也不上传，教师看到的是上一个班的名单，而他一编辑就会把上一个班的数据推进新账号的库。改为**退出登录时删掉记账**。
- 另外修掉**三处界面与事实不符**：登录成功但首轮同步被拒时弹的是绿色「数据正在同步」（现已按同步结果分档报红并给原因）；「清空全部数据」的说明在已登录时不成立（现已如实说明「只清本机，云端那份会取回来」）；「上次同步」把「本次打开」说成「这台设备」（现已改准）。以及**两处注释与实现不符**。

## v0.13.0 —— Phase 9A：本机存储层抽象 + 同设备跨标签页同步（2026-09-11，commit `feat: phase-9a cross-tab sync and storage layer`）

**同一台设备上开两个入口（两个标签页，或标签页 + 已安装的 PWA 窗口）不再各改各的**：一边改了，另一边立刻跟上，不会出现「后写的把先写的整份覆盖掉」。这一步是后端接入的**地基**，**不需要任何云账号**——云端的部分（换设备同步）仍是下一步。

### 新增

- **同设备跨标签页同步**：同一个浏览器里开着两个入口时，一边改了学生 / 座位 / 课表 / 请假 / 值日 / 周末返家 / 待办，另一边**不需要刷新**就会跟上。覆盖面是**八个可写模块的全部**。
- **导入备份 / 清空数据后，其它入口自动整页刷新**：这两种操作是「整份换数据」（键可能新增也可能消失），另一边会在你操作完的那一刻重新加载，不会停在旧数据上。

### 变化

- **全应用读写本机数据收成一处**（`src/services/storage.ts`）：此前八个 store 各写一份「读 → 判断 → 写 → 失败告警」，备份模块自带一份端口实现、工具箱页面又照抄一份——同一个动作有三处实现，改一处要记得改十处。现在是**一个出口、一份实现**，写盘**幂等**（内容没变就不写）——这正是两个入口不会互相触发、无限来回的根据。
- **冲突口径（需求方 2026-09-11 拍板）：最后写入胜出**。整份数据写一个键，没有字段级合并；同设备下这是够用的（改哪一页都是自己改的）。
- 版本号 `0.12.0` → `0.13.0`（`package.json` + `appConfig.version`）。

### 边界（重要，别误会）

- **只覆盖同一台设备**。换设备、换浏览器**都不同步**；**iPhone / iPad 上的 Safari 与「添加到主屏幕」的 PWA 是相互隔离的存储分区**，前端读不到同一份数据——**那里前端做什么都无效，只有接后端才能统一**（Phase 9B）。
- 其它入口导入备份 / 清空数据后，本页会**直接重新加载，不弹确认也不提示**：那一页上正在填的表单会被刷新掉。这是有意选的——那两种操作本来就是「整个应用的数据都换了」，再问一句只会让两页短暂地显示不同的数据；表单内容是即时提交的，没有真正的未保存数据。

## v0.11.0 —— Phase 7B：周末管理（2026-09-11，commit `feat: phase-7b weekend management`）

回答班主任每周五都要问的一句话：**这个周末谁不在学校**。工作日里学生回家住不住校，学校要的是「谁返家」这一件事的准确名单，所以这一期只做名单：**登记返家 = 一次点选若干学生**，留校不落库、由名单反推。周末管理因此不是请假的复制品——**不设审批、不记时长、不记离校 / 返校时间**（2026-09-11 需求方拍板，逐条见开发手册 §9.17）。
