## 2. 业务规则（不可违背）

### 2.1 学生住宿：全班统一住校

本班学生全部为住校生，**不存在走读情况**。因此：

- Student 数据模型**不应存在** `boarding` 字段；
- UI **不应出现**住宿 / 走读选择；
- 不应设计走读学生相关业务。

> **Phase 2.1 待处理：清理 boarding / 住宿走读相关遗留代码。**
> 当前代码中以下均为遗留，**尚未清理（交接日 2026-09-08 不动代码，排入 Phase 2.1 专项；日常开发不要顺手扩展走读逻辑）**：
>
> - `Student.boarding` 字段（`src/types/index.ts`，可选字段）
> - 表单「住宿情况」选择器 + 「宿舍」输入框（`StudentFormModal.vue`，含「走读时禁用宿舍」联动 watch）
> - 卡片与详情中的住宿 / 走读文案（经由 `formatBoardingLabel`，`src/utils/student.ts`）
> - 种子数据中 3 名走读学生（王小雨 / 陈思远 / 赵子轩，`boarding: false`，`src/services/mock.ts`）

### 2.2 周末返家：档案存「事实」，周末模块存「行为」

班主任需要依据学生家庭所在地，快速判断周末返家情况。**两个概念严格分开，不得混淆**：

| 概念           | 归属                     | 内容                                                           |
| -------------- | ------------------------ | -------------------------------------------------------------- |
| 家庭所在地事实 | 学生档案（Student）      | `familyAddress` / `familyLocation`，**静态行政事实**，长期不变 |
| 返家行为       | 周末管理（未来 Phase 7） | 某一个具体周末的**返家申请、审批、离校、返校、统计结果**       |

`familyLocation.scope` 只是家庭所在地的行政区划事实分类：

| 枚举值            | 中文         |
| ----------------- | ------------ |
| `changdu-city`    | 昌都市区     |
| `changdu-county`  | 昌都市其他县 |
| `outside-changdu` | 昌都市外     |

**红线**：

- scope 代表"家庭在哪个行政区域"，**不代表是否允许学生回家**；
- 代码中**永不出现** `canGoHome` 之类的字段，**不允许 AI 或规则从 scope 推导"能否回家"**；
- 是否批准返家属于周末管理模块的行为决策，由未来的周末管理数据承担；
- 学生档案只回答「学生是谁、基本信息、家庭地址在哪里」。

### 2.3 其他已确立规则

- **重名学生区分**：重名（如两名"旦增卓玛"）通过「姓名（学号后四位｜座位号）」识别，如 `旦增卓玛（0101｜1 号）`。展示名统一走 `formatStudentDisplayName()`，任何面向用户的场景（toast、确认框、详情标题、列表 meta）不得裸用 `name`。
- **删除语义**：删除 = 软删除（`deletedAt`），**当前无回收站入口**，对用户表达为「从学生列表中移除，无法撤销」。文案不得暗示"以后可以恢复"。
- **空值展示**：面向用户的空值一律显示占位「—」，不得渲染 `undefined` / `null` 文本。
- **中文文案**：界面文案使用中文，全角标点。

### 3.1 状态管理

进入 Pinia 的只有两个 store：

- `stores/app.ts`（`useAppStore`）：全局应用状态——`syncing` / `lastSyncedAt` + 模拟 `sync()`（Phase 0 占位逻辑，由 AppHeader「同步」按钮触发，注释注明"后续接入真实后端"）。
- `stores/student.ts`（`useStudentStore`）：学生领域数据，API 见 §7.2。

页面局部状态（搜索词、筛选、弹窗开关、表单）留在组件内，不进入 Pinia。

### 3.2 数据持久化（当前：Pinia → localStorage）

```
Pinia (students ref)
   ↓ deep watch
localStorage ('teacherdesk:students')
   ↓ 启动 load
Pinia (normalizeStudent 升级后回填)
```

- **为什么用 localStorage**：后端尚未接入（CloudBase / PostgreSQL 未开工），本地优先；先让班主任可离线使用，数据模型在真实接入前得到实战打磨。
- **存储键**：`appConfig.storageKeyPrefix + ':students'` → `'teacherdesk:students'`（`src/config/index.ts`）。
- **安全保护（全部已实现，勿回退）**：
  1. 首次启动（键不存在）→ 写入 8 名种子学生并返回；
  2. `JSON.parse` 整体包 `try/catch` → 失败仅告警并返回空列表，不崩溃；
  3. 解析结果经 `Array.isArray` 守卫 → 非数组（外部手工改动等）返回空列表；
  4. 逐条过滤非法元素（`typeof item === 'object'`）后 `normalizeStudent()` 升级；
  5. 持久化写入 `try/catch`（配额耗尽 / 隐私模式不中断应用）；
  6. 全部数组更新为**不可变更新**（spread + 重建数组），由 deep watch 触发写盘。
- **normalizeStudent 如何升级旧数据**（`src/utils/student.ts`，load 时逐条调用，不引入 migration 框架）：
  - 旧数据无 `familyAddress` → 归一为 `''`；非 string 同样归 `''`；
  - `familyLocation` **整体缺失 → 保留 `undefined`**（展示层显示「—」，不臆造分类）；
  - `familyLocation` 存在但 `scope` 无法识别 → 回退 `'changdu-county'`（本校学生以昌都籍为主）；
  - `prefecture` / `county` 非 string → 归 `''`；
  - 升级只发生在内存（load 后返回新对象）；首次写操作由 deep watch 自动把升级后的完整数据持久化，**旧数据不会被覆盖丢失**。

### 3.3 后端（未接入）

> **当前仍属于本地数据阶段，不要误认为数据库已接入。** `src/services/index.ts` 只有空壳占位 `export const api = {}`。
>
> 注意一处「注释与实现脱节」：`services/index.ts` 的注释声称"Phase 2 起所有业务数据访问都经由 `api.*`"，但实际 Student store 直接读写 localStorage，并未经由 api。该口径问题只记录不改动，Phase 9 接后端时统一（见 §9.3）。

## 5. 核心数据模型（`src/types/index.ts`）

### 5.1 Student —— 已使用（学生模块全量读写）

```ts
interface Student {
  id: string // UUID（crypto.randomUUID）
  name: string // 姓名
  studentNo: string // 学号（全局唯一，不区分大小写敏感；格式约定如 20230101）
  gender: 'male' | 'female'
  seatNumber?: number // 座位号；缺省 = 未排座（Phase 3 的核心数据基础）
  boarding?: boolean // ⚠ Phase 2.1 将移除（统一住校，见 §2.1）
  dormitory?: string // 宿舍文本（如「3 号楼 412」）；Phase 2.1 一并评估
  cadreRole?: string // 班委职务（班长/学习委员…）；留空 = 非班委
  tags?: string[] // 自定义标签
  phone?: string // 联系电话
  remark?: string // 备注
  familyAddress?: string // 家庭地址完整文本（Phase 2 增量，2026-09-08 加入）
  familyLocation?: FamilyLocation // 家庭所在地行政区划（同上；旧数据可能缺失）
  deletedAt?: string // 软删除时间 ISO；非空 = 已删除
}
type StudentInput = Omit<Student, 'id' | 'deletedAt'> // 新增/更新的可写字段
```

## 6. UI 体系

### 6.1 设计语言（Design Tokens，全部在 `src/styles/theme.css`）

Apple 风格 · 松石青主题。核心变量族：品牌色 `--color-primary: #2f8f83`（+ `-strong/-soft`、`--color-secondary`）、功能色（success/warning/danger，各含 strong/soft）、中性色（`--bg-main`、`--color-surface/text/text-secondary/text-faint/border*`）、间距 `--space-1~6`（4–24px）、字号 `--text-xs~xl`（12–22px）、圆角 `--radius-sm~xl`（8–20px）、阴影 `--shadow-sm/md/lg`、毛玻璃 `--glass-bg/--glass-blur`、动效 `--duration-fast/normal/slow` + `--ease-standard`、焦点环 `--ring-focus/--ring-danger`、层级 `--z-modal: 1000 / --z-toast: 1100`。

UnoCSS 主题与变量打通（`uno.config.ts`）：如 `text-primary`、`bg-canvas`、`text-ink-secondary` 等，但**新 UI 一律优先用 CSS 变量与组件 class**（与既有组件风格一致，不直接用魔法原子类拼业务样式）。

全局规范（`src/styles/main.css`）：系统字体栈（含 SF Pro SC / PingFang）、径向渐变背景、`:focus-visible` 焦点轮廓、`prefers-reduced-motion` 支持。

| API                                              | 语义                                                  | 返回                     |
| ------------------------------------------------ | ----------------------------------------------------- | ------------------------ |

## 11. 开发规范（Phase 3 起必须遵守）

### 11.1 代码

- **TypeScript strict**：全程类型安全；业务类型集中在 `src/types/index.ts`，禁止组件内散落重复类型。
- **Vue 3 Composition API**：`<script setup lang="ts">` + typed props（`withDefaults`）/ typed emits；组件间通过事件通信，禁止跨层 prop 钻透。
- **组件职责**：通用交互进 `components/ui/`（已验收组件不改视觉）；页面局部组织在 `views/<Module>/components/`；页面只做编排，业务规则进 store。
- **职责边界**：`utils/` 纯函数（展示/格式化/类型守卫，可被任意层引用）；`services/` 未来数据访问抽象；`stores/` 领域状态 + 持久化 + 数据层校验；业务逻辑不进 utils、不走组件的全局单例。
- **Pinia 使用规范**：setup-style；`ref` + deep `watch` 持久化；**数组一律不可变更新**；只有"会被多个页面/组件共享"的数据进 store。
- **注释**：中文注释解释"为什么"，不复述代码；注释必须与实现同步（发现脱节只修注释不改行为，除非另有指示）。
- **导入约定**：组件统一从 `@/components/ui`（index.ts）导入；路径别名 `@` → `src`。

### 11.2 UI

- 主题变量一律取自 `theme.css`（禁止硬编码颜色/圆角/间距）；新 token 先补 theme.css 再使用。
- 交互范式沿用现有验收样式：按钮 variant、Modal 确认流程、Toast 反馈、空态 EmptyState、Badge 语义色。
- 列表/卡片在桌面网格中保持不拥挤；中文文案 + 全角标点；空值占位「—」。
- 响应式底线：表单窄屏单列（≤560px media 已有先例）；不随意改变已验收 UI。

### 11.3 数据

- Student 写入必须经由 `studentStore`（add/update/remove），**不允许组件直接 push/修改 `students.value` 绕过 Store**；localStorage 键名必须以 `appConfig.storageKeyPrefix` 拼接。
- schema 演进一律走「load 时 normalize + 默认值回退」，不引入迁移框架；升级不得覆盖旧数据、不得让旧数据崩溃。
- 新字段保持向后兼容：历史数据缺失 → `undefined`/`''`，展示层给占位，不臆造默认业务值。
- 空值边界：`familyLocation` 缺失保留 `undefined`（不构造"假位置"）；scope 非法回退需在注释说明假设依据。
