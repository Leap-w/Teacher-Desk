## Phase 9A ✅ 后端接入第一小步：本机存储层抽象 + 同设备跨标签页 / 双入口同步（2026-09-11，tag v0.13.0）

> **需求方 2026-09-11 拍板**：Phase 9 拆成两小步，**先做地基（不需要云账号）**，云账号就绪后再接后端。范围为**单教师单班级**、**离线优先 / 联网同步**、冲突按**最后写入胜出**，数据库用 **CloudBase 内置文档型数据库**。**这一步解决技术债 #2**（同一浏览器开两个入口会丢更新）。

- **`src/services/storage.ts`（新增，本机存储的唯一出口）**：此前同一个动作有三处实现（八个 store 各写一份 `try + setItem + catch warn`、备份模块自带一份 `StoragePort`、工具箱页面又照抄一份），改一处要记得改十处；现在是 `StoragePort` + `localStoragePort` 一份实现，**Phase 9B 的云端替换点也在这里**。读语义分三态（键不存在 / 读到内容 / 损坏）：`readList` 给首屏加载用（损坏 → `[]` 且**不写盘**，原文保留），`readListStrict` 给同步用（读不到就别动内存）。**`writeJSON` 幂等**——盘上内容相同时不写、返回 `false`，这是跨标签页不会变成无限乒乓的承重条件
- **`src/services/sync.ts`（新增，同设备跨标签页同步）**：只广播**键名**（`{kind:'keys'}`），接收方从 localStorage 重读最新值再走该 store 的 `reviveXxx` 规范化——消息极小，且**旧版本 PWA 写下的数据会被当前版本的规范化逻辑收拾一遍**；导入备份 / 清空数据这类整批替换广播 `{kind:'reload'}`，接收方整页重载（`main.ts` 在 mount 前注册）。没有 `BroadcastChannel` 时静默降级为「不同步」，不让应用起不来
- **八个可写 store 全部接入**：`students` / `seatPlans` / `seatConstraints` / `timetable` / `leaves` / `duty` / `weekendReturns` / `dashboard:todos` 各一行 `syncPersisted(key, ref, reviveXxx)` 替代原先手写的写盘 watch；**`reviveXxx` 与首屏 `loadXxx` 共用同一份归一化实现**（同步路径也要刷新姓名快照，审查中修掉的一处分叉）
- **承重不变式**：幂等写 ⇒ 回声在第二次写盘处截断；每个 `reviveXxx` 幂等 ⇒ 有界收敛（第 2、3 轮必须完全静默）。实测「总线消息数 === 1 + 本轮真实写盘次数」
- **验证**：四项验证全通过（prettier --check / vue-tsc --noEmit / eslint / build）；**111** 个源文件（ts/vue）/ **19,505** 行；PWA **51** 个 precache 条目 / **1407.22 KiB**（v0.12.0 为 51 条 / 1407.47 KiB，**条目数不变、体积 −0.25 KiB**——无新路由，八处重复读写代码收成一处抵掉了新增的两个文件）。**跨标签页自检 79 项全过**：把「一个标签页」模块用 esbuild **打包三份**（三套独立模块图）共享一个内存 localStorage 桩与**真实 `BroadcastChannel`**，逐键统计 `setItem` 次数 + 总线上挂第三个观察者数消息——测的是「两个入口真的互相跟上 / 会不会乒乓」这类行为，不是「函数被调用了」；**6 组变异验证**（去掉幂等 → 写盘 660 次、总线 658→4830 条；广播变空操作 → 另一页跟不上；规范化非幂等 → 第 2 轮仍写 104 次；三条审查回归各自的变异精确失败在对应断言上）

## Phase 9B ✅ 后端接入：腾讯云 CloudBase 云端同步（2026-09-11，tag v0.14.0）

> **需求方 2026-09-11 拍板**：数据库用 **CloudBase 内置文档型数据库**（取代早先写的 PostgreSQL）；**单教师单班级**起步；**离线优先 / 联网同步**；冲突＝**最后写入胜出**；鉴权用 CloudBase 自带账号体系（**邮箱 + 密码**）。云环境 ID 已由需求方给出：`teacher-desk-d6gdsgqb8f9dc13d2`。规则与实现记录见开发手册 §9.20，逐项明细见 CHANGELOG。

- **三个新模块（新增 753 行）**：`services/remote.ts`（`RemotePort` / `RemoteDoc`——**引擎与 SDK 之间唯一的接缝**，自检就换在这里）；`services/cloudbase.ts`（**全应用唯一** import `@cloudbase/js-sdk` 的模块：auth v2 + 数据库 `.doc(id).set/get`，收拢 SDK 的两种失败模式）；`services/cloudSync.ts`（同步引擎，**不 import SDK**，因此能在自检里整段跑）
- **同步单元 = 一个存储键**（与 9A 一致）：**云端一份文档装一个键的整份数组**，文档 ID 就是键名（不做编码变换）；**不做字段级合并**——教师改哪一页都是他一个人改的，字段级合并换不来可见好处，却会引入「两边各改了一半、合起来谁都没写过」这种查不出的状态
- **本地磁盘就是待发队列**：没有单独的发送队列、没有内存待办表——**写盘即入队**，推成功后记下「这份原文已与云端对齐」（`seen`）。断网期间照常使用，联网后一轮把积压带上；进程被杀 / 页面刷新都不丢队列
- **判定表**（纯函数 `decideKey`，同步里唯一会出错的地方）：本地无此键 + 云端有 → 采纳；有 + 云端无 + 本地改过 → 推；**云端无 + 本地没改过 → 不动本地**（不把「云端缺失」当删除指令）；两边都有 + 本地没改过 → 云端更新过才采纳；两边都改了 → **首次同步以云端为准**，否则比「本地写盘时刻」与「云端 `updatedAt`」，**晚的赢**（平局判云端）
- **触发时机**（`main.ts` 在 mount **之前**注册）：应用启动 / 本页写盘后（**防抖 1500ms**）/ **一个新 store 第一次接进同步时**（store 懒加载，它一被打开就会播种示例数据，不去拉云端就会被当成「本地新数据」推上去盖掉真实数据）/ 重新联网 / 页面回到前台
- **状态与界面**：`cloudSyncState` 六态（`disabled` / `signedOut` / `syncing` / `idle` / `offline` / `error`）+ `checked` + `account`；工具箱新增**「云端同步」卡片**（未登录给登录 / 注册表单，已登录给状态点 / 账号 / 立即同步 / 退出登录，并**原样显示云端返回的原因**——不编「错误码 → 中文」对照表）
- **验证**：四项验证全通过（prettier --check / vue-tsc --noEmit / eslint / build，**交付前修复后全部复跑**）；**114** 个源文件 / **20,704** 行；PWA **50** 个 precache 条目 / **2175.36 KiB**（v0.13.0 为 51 条 / 1407.22 KiB，**+768.14 KiB**——CloudBase SDK 整包进主包，入口 chunk 906.41 kB；**首屏体积变大是本阶段最实在的代价**，记在案：若日后在意，可把 SDK 改成「登录时才动态 import」）。**云端同步自检 90 项 / 19 个场景全过**：把「一台设备」模块用 esbuild **打包两份**（两套独立模块图）共享一个内存里的假云端，配**可控假时钟**（每次写盘推进 1 秒）+ **手动驱动队列**（顶替 setTimeout，让防抖时刻成为确定事件）+ **请求流水**（断言发了几次、推了哪些键）；**13 组变异验证**（首轮 6 组 + 交付前修复复核 7 组，**每条都精确失败在对应断言上**：撤掉写盘时刻的新登记点一次就是 10 项失败）
