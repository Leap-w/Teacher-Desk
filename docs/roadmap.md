**V2.2 分解**：Cloud-1 `v2.2.0-alpha` Repository 数据访问层（Repository First）✅ → Cloud-2 `v2.2.1-alpha` 同步引擎（Queue/State/Conflict/Events，本地模拟；Sync Engine First）✅ → Cloud-3 `v2.2.2-alpha` CloudBase 单用户云同步（CloudTransport 真实通道、邮箱登录、自动同步四触发点、首次初始化确认、Local First + LWW）✅ → Cloud-4 `v2.2.3-alpha` 多设备验证与可靠性（双设备八模块验证、冲突与 LWW 验证、队列持久化、Outbox、同步诊断、指数退避与超时、CI 启用）✅ —— **V2.2 Cloud Foundation 收官**。

**V2.3 分解**：Classroom-1 `v2.3.0-alpha` 课堂工具（随机点名 / 课堂计时器 / 抽签；One-Tap Classroom）✅ → **RC-1 `v2.3.1-rc` 发布候选**（统一操作锁、导入后自动同步、课堂防连点、计时器后台恢复、快速返回；全站真机回归 + `docs/release-checklist.md`；**Stability Before Release**）✅ —— 此后 TeacherDesk 作为日常主力工作台投入真实教学使用，新功能（Classroom-2+ / 教学侧工具）建立在这套基线之上。

**节奏约定**：① 一阶段一 tag、一条 CHANGELOG、一段开发手册小节；② 架构规范只在阶段里立、不在阶段里破（Repository First / Sync Engine First / Consistency Before Features / Single User Cloud / One-Tap Classroom / **Observable Sync** / **Operation Lock**）；③ 新功能先补数据模型与仓储，页面不直连数据源；④ **正式发布前必须过 `docs/release-checklist.md`**。

> **2026-09-12 交付进展（Phase 5B，tag `v1.1.1`）**：**学生档案升级·检索 / 排序 / 批量编辑 / 卡片视觉**（见开发手册 **§9.25**，逐项明细见 `docs/CHANGELOG.md` 的 `v1.1.1` 条）——**版本号按需求方指定保持 `v1.1.1`**，tag 由 5A 提交**移动到本提交**；**不新增模块 / 路由 / 一级导航**，改动全在档案模块内部（加一处服务层与三处纯函数层新文件）。① **数据管道收敛成一个 computed**：`students → filter → sort → render` 全部收进列表页的 `visibleStudents`，规则本身在纯函数 `utils/studentQuery.ts`，store 的 `searchStudents()` 改为**委托**它（全应用只留一份检索/排序实现）。② **搜索增强**：haystack 补上 `cadreRole`（原先唯一缺失的字段，**搜「班长」是零结果**，而班主任最常找的就是班长和学习委员），保留 `name / studentNo / dormitory / tags`；关键词 trim + 小写；占位符改为「搜索姓名、班委、宿舍或标签…」。③ **固定三种排序**：**默认**（学号升序，**空学号一律排最后**——Phase 5A 允许空学号之后那批人原本顶在名单头部，是当时没预料的副作用）/ **首字母**（`pinyin-pro@3.29.4`，**同拼音保持原序**，比较相等即返回 `0` 交给 `sort` 的稳定性）/ **随机**（**每次点击重新洗牌**，含「已是随机时再点一次」；**当前会话保持结果**靠 `index.vue` 普通 `<script>` 块的模块作用域；**不写 localStorage、不修改 `students`**）。随机用**洗牌后的位置**当权重而不是随机数——随机数会撞值，撞值就得再定一条并列规则。**排序控件是分段按钮不是下拉**：下拉里选中已选中项**不派发 `change`**，「每次点击重新随机」用下拉做不到。④ **批量编辑**：入口「学生档案 → 批量管理」，**页内模式切换**；批量模式下点卡片 = 勾选（不是打开详情），**全选 = 选中当前可见的学生**（受搜索与筛选影响，「搜出走读生 → 全选 → 批量改宿舍」才连得起来）；可批量改宿舍（复用 5A 的固定 8 间）/ 班委（复用 `CADRE_OPTIONS`）/ 标签（添加、移除指定标签、自动去重），**暂不支持批量删除**；**「不修改」与「清空」用哨兵值分开**（混成一个，教师就永远批量清不掉一个字段——技术债 #20 正是这个形状）；性别不符的学生**跳过并报数**而非静默写入（`normalizeStudent` 的宿舍白名单会在下次加载时把它清掉，写进去也是一个会自己消失的值）；落库走 `applyStudentBatch()` **一次性替换数组 = 一次写盘 + 一次广播**，组件层绝不循环调 `updateStudent()`（选 30 人就是 30 次写盘 + 30 条广播）。⑤ **卡片视觉**（**不重构组件结构、不动 `AppCard` 本体**）：空字段规则固化成「**身份区用「—」、补充区整块隐藏**」，标签放开换行（`AppBadge` 自带 `nowrap`，不放开会**溢出卡片边界**）、间距统一到 `--space-3`、补 `:active` 下沉与 `:focus-visible` 焦点环；**只引用 `theme.css` 的变量，颜色体系一字未改**。⑥ **界面偏好键 `teacherdesk:studentView`**（本仓库第一份「纯界面状态」持久化）：搜索词与排序方式刷新后恢复，**随机不落盘**；**刻意不注册 `syncPersisted`** ——那个注册表同时是跨标签页与**云端**同步的名单，教师的搜索框内容不该被推到 CloudBase，更不该参与「最后写入胜出」的冲突判定。⑦ **依赖 `pinyin-pro` 走动态 `import()`**（与 `xlsx` 同一个模式）：产出独立分块 **312,387 字节**，**入口 chunk 体积与 Phase 5A 逐字节相同**（**917,700 字节** = 917.70 kB），三个特征串 grep 入口分块全部 0 命中；代价如实记下——首次点「首字母」多等一拍。**验证五项全过**，**常驻测试 115 → 170 项**（新增 `studentQuery.test.ts` 28 项 + `studentBatch.test.ts` 27 项）。**明确不做**：**学生头像**（`StudentAvatar.vue` 一行未动）、批量删除、云端头像存储、自动排座；规格的章节编号从「四」直接跳到「六」（**没有「五」**），无内容可做。**macOS 七项真机验收仍未做**，状态一字未变。

> **2026-09-12 交付进展（Phase 5A，tag `v1.1.1`）**：**学生档案升级**（见开发手册 **§9.24**，逐项明细见 `docs/CHANGELOG.md` 的 `v1.1.1` 条）——① **Excel 批量导入**（本阶段主体）：入口在档案页工具栏与空态，选 `.xlsx` / `.xls` → 五格统计 + 提示组 + 逐行预览 → 确认导入；`services/studentImport.ts` **切成两层**（`readSheetRows` 唯一碰 xlsx 且**动态 `import('xlsx')`**／`parseStudentRows` / `planStudentImport` 是**纯函数**，规则与统计全在这里，所以能在 node 常驻测试里直接喂数组跑）；**按学号追加合并**（命中的更新、没命中的新增，**绝不按姓名合并**）、**更新只覆盖这一行确实填了的字段**（空单元格＝本次没填，不是清空）、**被拦的行绝不进计划**、**空学号不参与匹配且每次导入都会新增**；**`checkFileSignature` 挡在 xlsx 之前**（SheetJS 会把改名成 `.xlsx` 的 CSV 当成功、按 latin1 解码，教师只会看到「没有找到「姓名」列」，错在格式而提示指向内容）；落库走 `studentStore.applyStudentImport` **一次性替换数组**（一次写盘 + 一次广播）。② **宿舍改固定 8 间**（女生2栋113–116 / 男生1栋209–212，唯一事实源在 `utils/student.ts`），旧自由文本由 `normalizeStudent` **白名单收敛**清空（**幂等**，比「一次性标记」多堵住「从备份 / 云端拉回旧值」这条路）。③ **`seatNumber` 撤出档案界面**（模型字段保留，「＋ 新建方案」仍按它自动就座；表单 payload 刻意不带该键；`formatSeatLabel` 已删）。④ **卡片改「班委 → 标签 → 宿舍 → 联系方式」**且不再显示返家信息；学号改选填（空值不查重，空值显示「—」）；班委加「＋ 自定义」。⑤ **展示名分两个口径**：档案走 `formatStudentShortName()`（不含座位号），座位图 / 请假仍走 `formatStudentDisplayName()`（**一字未动**）。**不碰座位图 / 请假 / 值日 / 周末 / 课表**；**常驻测试 81 → 115 项**；**xlsx 独立分包**（429.19 kB / gzip 141.77 kB），**入口 chunk 体积与上一版完全相同**（917,700 字节 = 917.70 kB），xlsx 也被 SW 预缓存（49 项 / 2616.75 KiB），离线可导入。⚠️ **升级前先在「工具箱 → 备份」导出一次 JSON**——**现有宿舍值会被清空**；**写盘文本变化还会让首次同步保护降级**（新设备首次同步会多问一次，不会丢数据）。**当时明确未做的排序 / 搜索增强 / 卡片视觉优化 / 批量编辑已由下方 Phase 5B 补齐**（学生头像 / 云端头像存储 / 自动排座新策略仍不做）。**macOS 七项真机验收仍未做**，状态一字未变。

- **Phase 2 · 最终语义（会影响已有数据，明说）**：① **同桌 = 同一排、同一列块**（1/2/3、4/5/6、7/8/9 各一张长桌），**1 号与 3 号隔着一个人也算同桌**——旧口径（左右紧邻）会**漏报**这种真冲突，判定因此**变严格**：教师此前录入的「不能同桌」现在可能报出以前不报的冲突，这是修正不是回归；② **相邻 = 四邻域（上下左右）**，**不含斜对角**，且**过道两侧不算相邻**（`3 ↔ 4`、`6 ↔ 7` 隔着过道，在真实教室里不是挨着坐）——修正前 `|Δrow|+|Δcol|===1` 会把它们判成相邻，判定因此**变宽松**（跨过道误报消失）；③ 前排 = 第 1~2 排、后排 = 第 5 排起，两个检查器共用同一份阈值。**数据结构与录入界面不变、历史约束条目原样保留**（只有口径变了）。
- **Phase 1 明确不做**：自动排座算法与 AI 排座、Student Store 结构改动、学生头像、CloudBase Storage、Widget / 课程表 / 首页改造、重写 SeatPlan、用临时数组 reverse 破坏真实座位数据、组件直写 localStorage、新 UI 框架。**Phase 2 明确不做**：不改双视角定义、不改 Excel「逐条应用」语义、不为「统一」破坏 Phase 3C/3D 已有功能、不合并两套约束的数据结构。
- **数据兼容**：旧方案缺 `constraints` → 补空约束（**升级不丢方案、不丢学生**）；更早期「只有数组顺序、没有 row/col」的数据按行优先下标做**一次性确定性迁移**（只在坐标整个缺失时兜底，越界坐标视为坏数据不收）；约束规范化在首屏加载 / 跨标签页同步 / 云端同步**三条路径共用一份实现**（去重、丢弃自相约束、前后排互斥）。
- **验证**：五项全过（prettier --check / vue-tsc --noEmit / eslint / **vitest run 238 项** / build）；常驻测试 **170 → 228（Phase 1）→ 238（Phase 2）项**；**两轮都用无头 Chrome + CDP 做了真机验收**（座位图结构 / 双视角可逆且不改数据 / 约束录入与结论 / **真选 Excel 文件**跑完整导入 + 取消不写盘 / **真点导出**并核对落盘的 PNG 与 PDF）。**未打 tag、未 deploy。**
- **遗留（如实记录）**：两套约束的**数据结构与入口仍未合并**（判定已统一；合并要重新设计「约束属于全班还是属于方案」）；**导入不写换座日志**（避免几十条淹没真正的调整记录，看差异用「方案对比」）；**未就座的学生不参与前后排检查**（与既有检查器一致）；**PDF 只做了落盘后的逐页核对，未重新设计导出**；语义变更**不回写历史数据**。
