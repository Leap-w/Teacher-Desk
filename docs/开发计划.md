## 一、总体结论

项目已从「学生档案 + 排座」的工具集，长成**班主任每天可以真正打开用的工作台**：首页（今日课程 / 待办 / 请假审批 / 今日值日 / 周末返家 / 班级概况）是入口，背后挂着七个成型的业务模块。

三点判断：

1. **日常可用度约 95%**——高频动作（看课、记事、查人、排座、批假、排值日、**记周末返家**）已闭环；**Phase 7B 交付后，周期性事务里的周末返家也补齐了**。**2026-09-12 补**：原先这里写「缺的主要只剩考勤」，考勤已按需求方拍板**不做**（见「未排期候选」的删除项与 §六 Phase 10），**不再计入缺口**——现有阶段的闭环没有已知的日常动作缺口，只是「事务记录 / 通知 / 工作安排」这些**还没排到**的东西没做。
2. **最大风险（数据丢失）已从「无法应对」降为「需教师配合」**：自 `v0.9.0` 起可一键导出 / 合并导入备份、可清空示例数据开始录真实数据，**`v0.10.1` 起工作台会在从未导出或超过 14 天未导出时主动提醒**（§五 #7 收口）；**`v0.14.0`（Phase 9B）起数据同时存在于云端**——清缓存、换设备、换浏览器之后，登录同一账号即可取回，风险再降一档（前提是教师先在控制台把环境准备好，见 §六 9B）。残余风险仍是「教师看到提醒也不导出」——提醒只负责让人想起来，不代劳（不做自动备份）。**云同步不替代导出备份**：云端存的是同一份数据的镜像，误删会一样地被同步上去或同步回来，而备份文件是独立于本机与云端的第二份副本。
3. **工程状态健康**：八个可写 store 同一套返回契约、类型 / 规则 / 视图三层分明、无第三方 UI 库、四项验证 + 交付前独立审查已固化为每个阶段的必走流程（§11.4）；**占位页自 Phase 6 起归零、占位卡片自 Phase 8 起归零**，每个一级导航与首页每一张卡片都是可用的真实内容；Phase 6 交付后做了一次全量审计（开发手册 §9.14）：UI Kit 零使用组件、调试残留、无用依赖、残留文件、版本号不一致**均为零**，仅有的重复实现已合并（`isPlainObject`、方案对比文案）并删除两个死类型。

**Phase 7 已于 2026-09-11 整阶段交付**：**7A** 抽「日期 + 上午 / 下午」公共流程骨架（纯重构，请假模块改走骨架并回归，**不单独打 tag**）；**7B** 用骨架落成周末管理模块（`/weekend` + 一级导航 + 返家登记 + 工作台卡片 + 数据管理第八块，tag **`v0.11.0`**，见 §六）。这一轮的工程价值不只在功能：**7B 是第一个「用骨架而不是复制骨架」实现的模块**——登记流程、日期端点形状、半天顺序键全部复用 7A 的公共件，所以新增代码集中在「周末返家与请假不一样的地方」（周末键、只加不删式批量登记、留校人数派生），没有出现第二套登记流程。**Phase 8 首页仪表盘整合（收尾）已于 2026-09-11 交付**（tag **`v0.12.0`**，见 §六）：工作台补上最后一张真卡片**「班级概况」**（在读人数 / 今日值日 / 本周末留校，点哪一行进哪个模块），`DashboardCard` 类型与占位卡渲染一并删除——**首页占位卡片归零**；同一阶段把**周末计数口径统一为「只算在读学生」**（`returnedCountOf` / `stayCountOf` / `staleCountOf` 上收进 store，跨卡片不再打架），并把值日判定上收 `dutyTodayState`（顺手纠掉两张卡片各说各话的自相矛盾）。按需求方拍板**不做出勤**（依赖考勤记录；**2026-09-12 补**：考勤记录已按拍板**不做**，出勤因此是「不做」而非「以后再说」）。**Phase 9A 已于 2026-09-11 交付**（tag **`v0.13.0`**，见 §六）：按需求方拍板 Phase 9 **拆成两小步**，这一步先做**地基、不依赖任何云账号**——把全应用读写 localStorage 收成**一个出口**（`services/storage.ts`），并在它之上加**同设备跨标签页 / 双入口同步**（`services/sync.ts`，只广播键名 + 幂等写）：同一个浏览器里开着两个标签页（或标签页 + 已安装的 PWA 窗口）时，一边改了另一边立刻跟上，**技术债 #2 落地**。**Phase 9B 亦已于 2026-09-11 交付**（tag **`v0.14.0`**，见 §六）：**腾讯云 CloudBase 云端同步**接入环境 `teacher-desk-d6gdsgqb8f9dc13d2`——新增 `services/remote.ts`（`RemotePort` 接口）+ `cloudbase.ts`（**全应用唯一**碰 `@cloudbase/js-sdk` 的模块）+ `cloudSync.ts`（引擎），**一个存储键 = 一份远端文档**；**本地磁盘就是待发队列**（写盘即入队），断网照常用、联网后一轮补齐；冲突按拍板口径**最后写入胜出**；工具箱新增**「云端同步」卡片**。**至此 Phase 9（后端接入）整阶段完成**：换设备、换浏览器、iOS 的 Safari 与「添加到主屏幕」PWA 之间都会自动对齐——**技术债 #2 与 §五 #2 的残余（跨端不同步）一并收口**。**路线图上的下一格是 Phase 10 班级事务、通知与轻量统计**（2026-09-12 需求方重排路线图：新插 Phase 10 / 11，macOS Widget 由 Phase 10 **顺延为 Phase 12**，数据源方案仍待拍板）——但**需求方同日明确「只做到 Phase 9，不再往后推进」，Phase 10 未开工，不要顺手起头**。同日还拍板三件减法：**考勤记录不做**、**多班级不做**、**值日增强精简**（去掉「打卡与完成情况统计」），三条都已从路线图相应位置结案。**顶栏那个 Phase 0 的假同步按钮**（§五 #15）同日拍板「接到真同步」并已落地（新增 `composables/useCloudSync.ts` 作为状态文案与「立即同步」的唯一来源，`stores/app.ts` 删除）。同时有两件**属于需求方拍板**的事留在 §五（#12 首屏体积、#13「清空全部数据」要不要同时清空云端）。

## 三、已完成内容（按「能给班主任做什么」）

### 1. 学生档案 ✅

62 人班级的底账。搜索（姓名 / 学号 / 宿舍 / 标签）+ 筛选、重名区分、详情 / 新增 / 编辑弹窗、软删除、学号唯一性双层校验；**家庭地址 + 家庭所在地（返家范围）已入库**——这是 Phase 7 周末管理的数据地基（已于 `v0.11.0` 落地；**注意两者互不派生**：档案记的是「家庭所在地事实」，周末模块记的是「某个周末的行为结果」，不存在 `canGoHome` 字段，也不从返家范围推返家资格）。

### 2. 座位管理 ✅（四个子阶段，功能最重的一块）

- **3A** 真实教室模型（7 排 × 9 列 · 3-3-3 分列 · 63 座）+ 老师 / 学生双视角网格 + 多方案管理
- **3B** 原生拖拽换座（交换 / 移入空位）+ 换座日志与「本次调整」摘要 + 长按信息卡
- **3C** 座位图导出 PNG / PDF、学生定位、约束检查器、方案对比（含对比 PDF）
- **3D** **自动排座**：硬约束必满足（不满足逐条报冲突）、软规则尽量满足、同种子结果确定、生成新方案可对比可撤销

### 3. 工作台 ✅

首页成为默认入口：今日课程（按星期自动切）、今日待办（点击完成、刷新保持）、快捷入口、本周课时统计、日期头部（30 秒刷新，跨零点翻篇）；**备份提醒**（v0.10.1 起）：从未导出过就常驻提示、距上次导出满 14 天转醒目态，点「去导出」直达 `/toolbox`，导出成功即消失。

### 4. 课程中心 ✅

`/schedule` 从只读数据源升级为**可编辑周课表**：手机分日列表 / PC 完整周视图、空格点选即新增、时段冲突拦截、临时代课标记；工作台与课表读同一份数据，增删改即时同步。

### 5. 请假 / 离校 ✅

`/leave` 覆盖**申请 → 审批 → 离校 / 返校登记**一条线：按「天 + 上午 / 下午」记录并自动算时长（跨月 / 跨年正确）；三态流转（待处理 → 批准 / 驳回）；「未离校 / 已离校 / 已返校」由时间戳派生；仅已批准可登记且校验时间线；工作台「请假审批」卡片同步待处理与本月已批准；学生被删除时记录保留、姓名快照冻结。

### 6. 云端同步 ✅（Phase 9B，`v0.14.0` 起）

同一账号下，把本机这份数据与云端那份对齐——**换设备 / 换浏览器 / iOS 的 Safari 与「添加到主屏幕」的 PWA 之间现在都能接着用同一份数据**（这两类入口此前是彼此隔离的存储分区，只有后端能统一）。入口在**工具箱的「云端同步」卡片**：用户名 + 密码登录（**不提供注册**，账号在 CloudBase 控制台建）、立即同步、退出登录，卡片上显示状态（已同步 / 正在同步 / 未登录 / 连不上云端 / 同步出错）与账号，出错时**原样显示云端返回的原因**。

口径与边界（教师可感知的部分）：**离线优先**——没网照常记录，联网后自动补齐；同一份数据两边都改过时按**最后写入胜出**（不做字段级合并）；**一个模块一整份**（不是逐条合并）。两条要注意的：① **本地清空 ≠ 云端清空**——「清空全部数据」只清本机，云端那份会在下一轮同步里被取回来（数据不丢，但「清空」不会真的空，是否加「同时清空云端」待需求方拍板，§五 #13）；② 在一台设备上删掉整份数据的意图**不会**传到另一台。

### 7. 工具箱 · 数据管理 ✅

`/toolbox` 从占位页升级为**数据备份与恢复**入口（不新增一级导航）：数据块的条目概览（交付时为六个，Phase 6 起七个——新增「值日安排」，Phase 7B 起八个——新增「周末返家」）；**导出备份（JSON）**（文件名带日期，记「上次导出」时间）；**合并导入**（按 id 合并：本机独有保留、备份独有追加、同 id 以备份为准，导入前先给出「新增 / 覆盖 / 保持不变」预览）；**清空示例数据**（列出待删名单后可一键清掉示例学生 / 课程 / 待办 / 请假及其座位约束，保留教师自己录入的内容）；**清空全部数据**（恢复到首次打开的状态）。数据全部丢失的红灯风险由此转为可控。概览里未生成的模块显示「**还没打开过**」（v0.10.1 起，原为开发者口径的「未初始化」）；存在旧课表存档时，「清空全部数据」会明确告知该存档一并删除、**不在备份范围内**、删后无法找回。**v0.14.0（Phase 9B）起，这一页还多一张「云端同步」卡片**（登录 / 立即同步 / 退出；**v0.14.0 交付时还有注册，2026-09-12 按需求方要求去掉**，账号改在云开发控制台建，见上 §三 6）——同步入口与备份入口放在同一页，是因为它们是同一件事的两种形态：把数据放到别处留一份。

## 六、后续开发计划

### 近期增量：数据管理 ✅（`v0.9.0` 已交付）

**动因**：localStorage 是当前唯一数据载体，清缓存 / 换设备即全部丢失；这是本项目唯一的红灯级风险。

**拍板与落地**（需求方决定）：

- **导入策略 = 合并式**（不是覆盖式）：本机独有的记录原样保留、备份独有的追加、同 id 以备份为准；**合并从不删除当前数据**。为了不让「同 id 覆盖」悄悄发生，导入前先给出**逐块预览**（新增 / 覆盖 / 保持不变）。
- **清空 = 两档**：清空示例数据（保留教师自己录入的内容）+ 清空全部数据（回到首次打开的状态）。
- **交付 tag = `v0.9.0`**；入口 `/toolbox`（不新增一级导航）。

**实现取舍（详见 CHANGELOG 与开发手册 §9.12）**：备份按**存储层**读写原始 JSON，条目级校验仍由六个 store 的 `normalize*` 在重载后把关（不写第二套规则）；写盘整批原子化，失败即回滚，界面不得对教师说「数据未改变」而实际写了一半；缺 id 的条目照常导入（追加），读不动的数据块绝不写盘。

**已知边界**：手动备份（无提醒，见 §五 #7）；示例识别按 id 前缀（§五 #8）；概览数字只看磁盘已存在的键（§五 #9）；旧课表键不在「清空示例数据」范围内（§五 #10）。

### Phase 6 值日管理 ✅（`v0.10.0` 已交付）

**动因**：把每周要重复交代的事固化下来——值日表排一次、之后每天自动轮到谁清清楚楚。

**拍板与落地**（需求方 2026-09-10 定，六个问题逐条回答）：

- **轮换粒度 = 按天**；**只排「值日组」不分工位**（扫地的组与拖地的组不分家）；**本阶段不做打卡**，先只做编排与轮换；**分组由教师手动指定**（不按座位区 / 小组自动切分）；**周末是否值日做成开关由教师自定**（默认关＝周六周日不排，周末不消耗轮换位）；**工作台加一张「今日值日」卡片**。
- **交付 tag = `v0.10.0`**；入口 `/duty`（不新增一级导航）；**最后一个占位页消失**，`PagePlaceholder` 组件与文档引用一并删除。

**实现取舍（详见 CHANGELOG 与开发手册 §9.13）**：值日组与轮换设置**同存一个数组**（`kind` 区分），备份 / 合并 / 清空 / 概览因此零改动复用；轮换用「起点日期 + 起点组」一个基准推进（不存整张历史表），起点之前的日子按同一基准往前倒推；**日期算术逐日推进而不是「天数差减周末数」**——算错一次就是整张表错位，代价是起点年份必须设闸（2000–2099，读 / 写 / 纯函数三处都挡）。

**已知边界**：无打卡与完成情况统计、无工位分工、无按周 / 按月轮换、无节假日与调休日历（调休后需教师手动把起点改回今天）、无同一天多场景并行、无打印导出与提醒；起点组被删时轮换自动顺延但要教师确认。
