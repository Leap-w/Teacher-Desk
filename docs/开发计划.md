## 一、总体结论

项目已从「学生档案 + 排座」的工具集，长成**班主任每天可以真正打开用的工作台**：首页（今日课程 / 待办 / 请假审批 / 今日值日 / 周末返家 / 班级概况）是入口，背后挂着七个成型的业务模块。

三点判断：

1. **日常可用度约 95%**——高频动作（看课、记事、查人、排座、批假、排值日、**记周末返家**）已闭环；**Phase 7B 交付后，周期性事务里的周末返家也补齐了**。**2026-09-12 补**：原先这里写「缺的主要只剩考勤」，考勤已按需求方拍板**不做**（见「未排期候选」的删除项与 §六 Phase 10），**不再计入缺口**；同日还拍板 **Phase 10 / 11 取消**——「事务记录 / 通知 / 工作安排」这些**不是「还没排到」，而是「不做」**（理由：这个工具是工作台，不是记录系统）。**因此闭环的口径至此稳定：现有八个模块就是全部**，下一步只剩 Phase 12 的 macOS Widget（只读展示，不加模块）。**2026-09-12 再补（Phase 5A）**：学生档案升级（`v1.1.1`）交付——**批量化建档**（Excel 导入）、宿舍固定 8 间、卡片顺序调整，**全在既有模块内部改，没有新增第九个模块**，上面这条口径不变；同时把「**导入进来的人还需要手工补返家范围吗**」这类批量操作与必填项的矛盾显式处理掉了（返家范围做成可选列，认不出就提示，不拦）。~~**Phase 5B 的排序 / 搜索增强 / 头像 / 卡片重构 / 批量编辑一行都没写**——需求方明确禁止提前开发。~~ **2026-09-12 同日已交付**（Phase 5B，同 tag `v1.1.1`）：排序 / 搜索增强 / 卡片视觉 / 批量编辑四项补齐；**学生头像按需求方「不再做学生头像了」不做**（`StudentAvatar.vue` 一行未动）。**2026-09-12 再补**：Phase 12 的 macOS 代码**已随 `v1.0.0` 入库**（独立 Xcode 工程 `macos/`，宿主 App + 三个只读 Widget，工程自检六档全绿），**但七项真机验收一项都还没验**——**入库不等于验收：它不是「已完成」，是「待在真机验收」**，见 §六 Phase 12 与开发手册 §9.22。同日 **Web / PWA 正式上线（`v1.0.0`）**——发布到 CloudBase 静态网站托管，见 §二 与 §六 上线一节。
2. **最大风险（数据丢失）已从「无法应对」降为「需教师配合」**：自 `v0.9.0` 起可一键导出 / 合并导入备份、可清空示例数据开始录真实数据，**`v0.10.1` 起工作台会在从未导出或超过 14 天未导出时主动提醒**（§五 #7 收口）；**`v0.14.0`（Phase 9B）起数据同时存在于云端**——清缓存、换设备、换浏览器之后，登录同一账号即可取回，风险再降一档（**教师已在 2026-09-12 把控制台环境准备好**，见 §六 9B）。残余风险仍是「教师看到提醒也不导出」——提醒只负责让人想起来，不代劳（不做自动备份）。**云同步不替代导出备份**：云端存的是同一份数据的镜像，误删会一样地被同步上去或同步回来，而备份文件是独立于本机与云端的第二份副本。
3. **工程状态健康**：八个可写 store 同一套返回契约、类型 / 规则 / 视图三层分明、无第三方 UI 库、**五项验证（含常驻回归测试）+ 交付前独立审查**已固化为每个阶段的必走流程（§11.4）；**占位页自 Phase 6 起归零、占位卡片自 Phase 8 起归零**，每个一级导航与首页每一张卡片都是可用的真实内容；Phase 6 交付后做了一次全量审计（开发手册 §9.14）：UI Kit 零使用组件、调试残留、无用依赖、残留文件、版本号不一致**均为零**，仅有的重复实现已合并（`isPlainObject`、方案对比文案）并删除两个死类型。**2026-09-12 Phase 9C 补**：此前「每次改动临时写一份自检脚本、跑完即删」的做法**是这套工程状态里唯一的软肋**——同一件事被反复重写、漏了就没人知道，9A / 9B 各有一批脚本因之蒸发。现在换成**仓库内常驻的 81 项回归测试**（`npm run test`，离线可跑、不连真 CloudBase）：**同步判定 / 存储层 / 各域 `revive*` 与 normalize / 备份与清空**这四类承重逻辑从此改坏了会当场失败。这也是 9C 唯一的产出——**一行业务功能都没加**。

**Phase 7 已于 2026-09-11 整阶段交付**：**7A** 抽「日期 + 上午 / 下午」公共流程骨架（纯重构，请假模块改走骨架并回归，**不单独打 tag**）；**7B** 用骨架落成周末管理模块（`/weekend` + 一级导航 + 返家登记 + 工作台卡片 + 数据管理第八块，tag **`v0.11.0`**，见 §六）。这一轮的工程价值不只在功能：**7B 是第一个「用骨架而不是复制骨架」实现的模块**——登记流程、日期端点形状、半天顺序键全部复用 7A 的公共件，所以新增代码集中在「周末返家与请假不一样的地方」（周末键、只加不删式批量登记、留校人数派生），没有出现第二套登记流程。**Phase 8 首页仪表盘整合（收尾）已于 2026-09-11 交付**（tag **`v0.12.0`**，见 §六）：工作台补上最后一张真卡片**「班级概况」**（在读人数 / 今日值日 / 本周末留校，点哪一行进哪个模块），`DashboardCard` 类型与占位卡渲染一并删除——**首页占位卡片归零**；同一阶段把**周末计数口径统一为「只算在读学生」**（`returnedCountOf` / `stayCountOf` / `staleCountOf` 上收进 ### 6. 云端同步 ✅（Phase 9B，`v0.14.0` 起）

同一账号下，把本机这份数据与云端那份对齐——**换设备 / 换浏览器 / iOS 的 Safari 与「添加到主屏幕」的 PWA 之间现在都能接着用同一份数据**（这两类入口此前是彼此隔离的存储分区，只有后端能统一）。入口有两处：**工具箱的「云端同步」卡片**（用户名 + 密码登录 —— **不提供注册**，账号在 CloudBase 控制台建 —— 、立即同步、退出登录，卡片上显示状态（已同步 / 正在同步 / 未登录 / 连不上云端 / 同步出错）与账号，出错时**原样显示云端返回的原因**）与**顶栏右上角的「同步」按钮**（每页都在；2026-09-12 起接到真同步，此前是 Phase 0 留下的假动画）。两处的状态文案与提示取自同一份实现（`composables/useCloudSync.ts`），不会互相矛盾。

口径与边界（教师可感知的部分）：**离线优先**——没网照常记录，联网后自动补齐；同一份数据两边都改过时按**最后写入胜出**（不做字段级合并）；**一个模块一整份**（不是逐条合并）。两条要注意的：① **本地清空 ≠ 云端清空**——「清空全部数据」只清本机，云端那份会在下一轮同步里被取回来（数据不丢，但「清空」不会真的空，是否加「同时清空云端」待需求方拍板，§五 #13）；② 在一台设备上删掉整份数据的意图**不会**传到另一台。

### 7. 工具箱 · 数据管理 ✅

`/toolbox` 从占位页升级为**数据备份与恢复**入口（不新增一级导航）：数据块的条目概览（交付时为六个，Phase 6 起七个——新增「值日安排」，Phase 7B 起八个——新增「周末返家」）；**导出备份（JSON）**（文件名带日期，记「上次导出」时间）；**合并导入**（按 id 合并：本机独有保留、备份独有追加、同 id 以备份为准，导入前先给出「新增 / 覆盖 / 保持不变」预览）；**清空示例数据**（列出待删名单后可一键清掉示例学生 / 课程 / 待办 / 请假及其座位约束，保留教师自己录入的内容）；**清空全部数据**（恢复到首次打开的状态）。数据全部丢失的红灯风险由此转为可控。概览里未生成的模块显示「**还没打开过**」（v0.10.1 起，原为开发者口径的「未初始化」）；存在旧课表存档时，「清空全部数据」会明确告知该存档一并删除、**不在备份范围内**、删后无法找回。**v0.14.0（Phase 9B）起，这一页还多一张「云端同步」卡片**（登录 / 立即同步 / 退出；**v0.14.0 交付时还有注册，2026-09-12 按需求方要求去掉**，账号改在云开发控制台建，见上 §三 6）——同步入口与备份入口放在同一页，是因为它们是同一件事的两种形态：把数据放到别处留一份。

## 六、后续开发计划

### 近期增量：数据管理 ✅（`v0.9.0` 已交付）

**动因**：localStorage 是当前唯一数据载体，清缓存 / 换设备即全部丢失；这是本项目唯一的红灯级风险。

**拍板与落地**（需求方决定）：

- **导入策略 = 合并式**（不是覆盖式）：本机独有的记录原样保留、备份独有的追加、同 id 以备份为准；**合并从不删除当前数据**。为了不让「同 id 覆盖」悄悄发生，导入前先给出**逐块预览**（新增 / 覆盖 / 保持不变）。
- **清空 = 两档**：清空示例数据（保留教师自己录入的内容）+ 清空全部数据（回到首次打开的状态）。
- **交付 tag = `v0.9.0`**；入口 `/toolbox`（不新增一级导航）。

**实现取舍（详见 CHANGELOG 与开发手册 §9.12）**：备份按**存储层**读写原始 JSON，条目级校验仍由六个 store 的 `normalize*` 在重载后把关（不写第二套规则）；写盘整批原子化，失败即回滚，界面不得对教师说「数据未改变」而实际写了一半；缺 id 的条目照常导入（追加），读不动的数据块绝不写盘。

**已知边界**：手动备份（无提醒，见 §五 #7）；示例识别按 id 前缀（§五 #8）；概览数字只看磁盘已存在的键（§五 #9）；旧课表键不在「清空示例数据」范围内（§五 #10）。

### Phase 6 值日管理 ✅（`v0.10.0` 已交付）

**动因**：把每周要重复交代的事固化下来——值日表排一次、之后每天自动轮到谁清清楚楚。

**拍板与落地**（需求方 2026-09-10 定，六个问题逐条回答）：

- **轮换粒度 = 按天**；**只排「值日组」不分工位**（扫地的组与拖地的组不分家）；**本阶段不做打卡**，先只做编排与轮换；**分组由教师手动指定**（不按座位区 / 小组自动切分）；**周末是否值日做成开关由教师自定**（默认关＝周六周日不排，周末不消耗轮换位）；**工作台加一张「今日值日」卡片**。
