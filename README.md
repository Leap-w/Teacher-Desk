# TeacherDesk

面向高中班主任的综合工作台（Web / PWA，本地优先）。以班级日常事务为核心，逐步覆盖学生档案、座位编排、课程表、请假审批、值日管理、周末管理等场景；数据**本地优先 + 云端同步**（腾讯云 CloudBase 的**内置文档型数据库**，v0.14.0 起同一账号可在换设备 / 换浏览器时接着用同一份数据），后续支持 macOS Widget。

> **开发交接**：当前状态、业务规则、技术架构与开发规范的详细说明见 [docs/开发手册.md](docs/开发手册.md)；阶段规划见 [docs/roadmap.md](docs/roadmap.md)；进展评估与后续安排（含待拍板事项）见 [docs/开发计划.md](docs/开发计划.md)。

自动排座（Phase 3D）已完成：**约束求解**——硬约束（不能同桌 / 不能相邻）必满足，无法满足则不生成方案并逐条说明冲突；软规则（坐后排 / 坐前排 / 同区块，取值域约束的三个预留规则位）尽量满足，未满足的部分由约束检查面板逐条提示；「高个」标签自动获得低权重后排偏好（显式规则优先）。生成结果落为**新方案**（原方案原样保留，可对比 / 可随时切回），支持「换一种排法」（换种子重排，沿用同一方案名不堆积）与「撤销」（切回原方案并删除新方案）。同一输入与种子结果确定（种子随机数 + 贪心 + 局部搜索，无外部依赖）。数据当前保存在浏览器 localStorage。

值日管理（Phase 6）已完成：`/duty` 从占位页变为**值日编排与轮换**页面，覆盖建组 → 设起点 → 每天自动排班一条线。值日组由教师**手动指定**组员（候选名单按学号排序、支持搜索，已不在档案的成员保留并标注，同一学生可在多组但会提示），**列表顺序就是轮换顺序**；轮换**按天**推进——设好「起点日期 + 起点组」后每天顺延一组、循环往复，**周末是否排值日**由教师开关决定（默认关＝周六周日不排、周一接着上一组继续，周末不消耗轮换位），起点落在周末或设为未来某天时都有明确的顺延 / 倒推口径，轮换说明与排出来的表同源。页面给出**今日值日**（组 + 组员）与**接下来 7 天**列表（周末标「不值日」、今天高亮）；起点组被删除时轮换自动顺延到下一组并提示重设。工作台新增全宽的**今日值日**卡片：今天的组 + 组员标签（最多 8 个，其余折叠）+「接下来：明天由「第 2 组」值日」，今天不值日时说明「周一继续轮到下一组」。**本阶段不做打卡与工位分工**，只做编排与轮换。数据保存在浏览器 localStorage（键 `teacherdesk:duty`；仅在学生档案仍是示例数据时才播种示例值日组），并已接入数据管理的备份 / 合并 / 概览 / 清空示例。

周末管理（Phase 7B，v0.11.0）已完成：`/weekend` 是**新的一级入口**，只回答一个问题——**这个周末谁返家了**。页面顶部是周末切换条（下周末 / 本周末 / 上周末，各标本期返家人数），分节头写明是哪个周末（如「本周末 · 9月12日 – 9月13日」）并给出**返家几人 / 留校几人**；下面按姓名升序列出本期返家名单，每行可撤销（二次确认）。点「登记返家」在抽屉里勾选学生即可，**候选名单是在读学生全员**，已登记的人显示「已登记」徽标并禁用勾选——两个入口重复登记同一人不会产生两条记录。**留校不建记录**：留校人数永远是「在读学生数 − 本期返家人数」算出来的，不会出现两个数各算各的；**不设审批**、**不记时长**、**不记离校 / 返校的具体时刻**，只记「这个周末是否返家」。工作台新增「周末返家」卡片（本期 + 人数 + 姓名标签 + 本月累计人次，点开直达）。**一个周末以该周周六的日期键标识**（周日登记归到前一天，周一到周五不能登记），不用「第几周」这种编号——避免跨年时归属算错。数据保存在浏览器 localStorage（键 `teacherdesk:weekendReturns`；仅在学生档案仍是示例数据时才播种示例记录），并已接入数据管理的备份 / 合并 / 概览 / 清空示例。

首页仪表盘整合（Phase 8，v0.12.0）已完成：工作台补上最后一张真卡片**「班级概况」**——三行回答「这个班现在什么情况」：**在读人数**（另有几位已退档、不计入，一并说明）、**今日值日**（组名；今天不值日或还没设起点时说明原因，并给出「接下来：明天由「第 1 组」值日」）、**本周末留校**（同时给出「返家 N 人」）。**点哪一行就进哪个模块**（学生档案 / 值日管理 / 周末管理）。至此**首页八张卡片全部是真数据、占位卡片归零**；**「出勤」按需求方拍板本阶段不做**——它依赖考勤记录，卡片只有三行，不留占位、不假装有数据。**2026-09-12 补**：考勤记录已按需求方拍板**不做**，所以「出勤」是**不做**而不是「以后再说」。同一阶段统一了**周末计数口径**：所有人数**一律只算在读学生**，已退档学生的历史记录仍列在周末页名单里、标注「已不在档案」、但不计入任何数——因此「在读 N 人 = 留校 S 人 + 返家 R 人」在班级概况卡片、周末返家卡片与周末页里处处成立，不会出现两张卡片加起来超过班级人数的画面。

跨标签页同步（Phase 9A，v0.13.0）已完成：**同一台设备上开两个入口**（两个标签页，或标签页 + 已安装的 PWA 窗口）时，一边改了学生 / 座位 / 课表 / 请假 / 值日 / 周末返家 / 待办，**另一边不需要刷新就会跟上**——不再出现「两个窗口各改各的、后写的把先写的整份覆盖掉」。在另一入口**导入备份 / 清空数据**后，这一边会自动整页刷新（那两种操作是整份换数据，键可能新增也可能消失），**不弹确认也不提示**——它本来就是「整个应用的数据都换了」的操作。这一步是后端接入的**地基**，**不需要任何云账号**：全应用读写本机数据收成**一个出口**（`services/storage.ts`，写盘**幂等**——内容没变就不写，两个入口因此不会互相触发、无限来回），八个模块统一接入同步层。**边界（别误会）**：它**只覆盖同一台设备**——**换设备、换浏览器都不同步**，而 **iPhone / iPad 上的 Safari 与「添加到主屏幕」的 PWA 是相互隔离的存储分区**，前端读不到同一份数据，**只有接后端才能统一**（Phase 9B）。冲突按需求方拍板取**最后写入胜出**（整份数据写一个键，没有字段级合并）。

云端同步（Phase 9B，v0.14.0）已完成：**同一个账号下，换设备 / 换浏览器看到的是同一份数据**——手机记的请假、电脑录的座位，各端会自动对齐；iPhone / iPad 上 Safari 与「添加到主屏幕」的 PWA 那两套彼此隔离的存储分区，也正是靠这一步统一的。入口有两处，说的是同一件事：**工具箱页面的「云端同步」卡片**（用户名 + 密码登录 —— **不提供注册**，账号在 CloudBase 控制台「身份认证 → 用户管理」建，见下 —— 、**立即同步**、**退出登录**，卡片显示状态与当前账号，出错时**原样显示云端返回的原因**），以及**顶栏右上角的「同步」按钮**（每一页都在，点一下就同步一次，并在旁边显示上次同步的钟点；没登录时点它只提示一句、把你送到工具箱去登录）。两处的状态文案与提示取自**同一份实现**（`composables/useCloudSync.ts`），不会出现一个地方说「已同步」、另一个地方说「未登录」。同步在四个时刻自动发生：应用启动、本页改动之后（合并连续编辑，1.5 秒后发一次）、重新联网、页面回到前台——不需要记着点同步。**数据仍然本地优先**：改动先写在本机（磁盘就是待发队列），没网照常记录，联网后一轮补齐，刷新 / 关掉重开都不丢。**口径与边界**：一个模块 = 云端一份文档、**整份对齐**（不做字段级合并）；两边都改过时按**最后写入胜出**，首次同步以云端为准（新设备装上就该看到已有数据，而不是把它自己播种的示例数据推上去）。三条要注意的：① **首次使用要在 CloudBase 控制台做准备**（为环境 `teacher-desk-d6gdsgqb8f9dc13d2` 开启**用户名密码登录**、建 `teacherdesk` 集合、权限选**「仅创建者可读写」**——**不要用「匿名登录 + 所有人可读」**，一个账号里装的是全班学生的姓名 / 学号 / 家庭住址 / 请假与返家记录）；② **本地清空 ≠ 云端清空**——「清空全部数据」只清本机，云端那份会在下一轮同步里被取回来（数据不丢，但「清空」不会真的空）；③ **在一台设备上删掉整份数据的意图不会传到另一台**（云端「没有这个键」是合法状态，不当作删除指令）。另：CloudBase SDK 使首屏体积增加约 768 KiB（PWA 预缓存 1407 → 2175 KiB）。

数据管理（近期增量，v0.9.0）已完成：`/toolbox` 从占位页变为**数据备份与恢复**入口。页面上先给出八个数据块的条目概览（学生档案 / 座位方案 / 座位约束 / 课程表 / 今日待办 / 请假记录 / 值日安排 / 周末返家），再是**导出备份（JSON）**（一键下载 `teacherdesk-backup-日期.json`，并记下「上次导出」时间）与**导入备份**。导入采用**合并式**：选择文件后先给出逐块预览（新增几条 / 覆盖几条 / 保持不变几条），确认后才写盘并重载——本机独有的记录原样保留、备份独有的追加、同一 id 以备份为准，**合并不会删除当前数据**；被覆盖的版本无法找回，弹窗内可直接「先导出当前备份」。危险操作区提供两档清空：**清空示例数据**（删除首次打开时自动生成的示例学生 / 课程 / 待办 / 请假及其座位约束，保留你自己录入的内容；确认弹窗会列出待删名单，因为按编号识别的示例记录若被你改成了自己的内容也会一并删除）与**清空全部数据**（恢复到首次打开的状态）。本机数据若某块读取异常，概览会显示「读取异常」，导入与清空示例都会跳过它，避免覆盖还能人工找回的原文。

稳定性增量（近期增量，v0.10.1）已完成：**不加新模块**，补两件事。① **工作台备份提醒**——首页新增一条提示：**从未导出过备份**时常驻「还没有导出过备份，数据只保存在这台设备上。」，**距上次导出满 14 天**转为醒目提示（写明已过天数与后果），点「去导出」直达 `/toolbox`，导出成功后立即消失；判定**只看「上次导出时间」这一个时间戳**，不做数据变更感知，也不会自动备份（宁可多提醒一次，也不漏）。② **PWA 正式 PNG 图标**——桌面 / 主屏图标由 SVG 占位换成四张正式 PNG（192 / 512 / 512 maskable 满幅 / apple-touch-icon 180），`favicon.svg` 保留；同时给 Service Worker 补上 `png` 匹配。另修掉 **8 处**「确认删除后弹窗 / 抽屉还在播淡出动画、名字已被清空」的显示缺陷（其中最扎眼的是课程抽屉标题会从「编辑课程」翻成「新增课程」），工具箱概览里未生成的模块改说「还没打开过」，清空全部数据时会明确告知旧课表存档一并删除。**既有数据零迁移**：只加提示与图标，未动存储结构与备份格式。

### 云端同步（可选，v0.14.0 起）

不配也能用——**不登录时应用完全按本地模式运行**，云端同步卡片会提示未登录。要用同步，先做两件事：

1. **云侧准备（一次性，在 CloudBase 控制台做）**：为环境 `teacher-desk-d6gdsgqb8f9dc13d2` 开启**用户名密码登录**方式 → 在**「身份认证 → 用户管理」里把账号建出来** → 建一个名为 **`teacherdesk`** 的集合 → 权限选**「仅创建者可读写」**。⚠️ **不要用「匿名登录 + 所有人可读」**：一个账号里装的是全班学生的姓名 / 学号 / 家庭住址 / 请假与返家记录。⚠️ **建账号时把「邮箱验证」关掉**：应用里没有输入验证码的地方，开着它账号会停在未验证、**登录必被拒**（要留就把验证方式设成「验证链接」，别用「验证码」）。
2. **应用内登录**：工具箱 →「云端同步」→ 用户名 + 密码（**控制台「新建用户」建的那个用户名**，不是邮箱——`2026-09-12` 起应用改走用户名登录，理由见开发手册 §9.20 取舍 ⑪）。**应用里不提供注册**（网站单教师自用，账号在控制台建）。

要指向别的环境：`VITE_CLOUD_ENV_ID=<环境ID> npm run dev`（默认值写在 `src/config/index.ts` 的 `cloudEnvId`）。

设计口径与边界（最后写入胜出、无删除传播、本地清空 ≠ 云端清空等）见 [docs/开发手册.md](docs/开发手册.md) §9.20。
